# 思远物流系统手册（当前版本）

更新时间：2026-06-08  
适用范围：当前本地 MVP / 前端闭环版本  
系统名称：思远物流 AI TMS / OMS

## 1. 系统概览

思远物流是一套面向跨境物流公司的 TMS / OMS 系统。当前版本重点覆盖员工端与客户门户的第一版业务闭环，核心目标是让业务员、客服、仓库操作、财务和管理员围绕同一批运单协同工作。

系统当前支持：

- 运营工作台：查看全局待办、风险和 AI 建议。
- 运单履约：管理出货订单从创建、审核、入库、排货、发货、轨迹到签收的流程。
- 渠道排货：处理渠道/代理分配、转单号补齐和排货侧数据查看。
- 收货打单：承接审核后的订单，处理入库、面单申请和收货确认。
- 轨迹监控：跟进承运商轨迹、未上网、未更新和客户可见轨迹。
- 问题件中心：处理异常件、退货、滞留、客户沟通和关闭。
- 报价查价：导入价格表、维护加价规则、查询业务员报价。
- 财务结算：应收、对账、收付款、核销和余额流水。
- 基础资料：维护客户资料和代理资料。
- 系统设置：管理员维护账号、角色权限、审计和系统基础配置。
- AI 助手：在多个模块中生成建议、解释异常、辅助回复和风险提示。

当前版本以“可演示、可验证、可扩展”为目标。真实承运商 API、真实打印客户端、电子秤、PDA、微信入口、自动对账等能力已预留业务位置，但不是当前版本的真实生产能力。

## 2. 基础概念

### 2.1 单号定义

| 名称 | 系统含义 | 使用场景 |
| --- | --- | --- |
| 客户单号 | 内部单号，由客户或业务侧提供 | 查件、导入轨迹、客户对账 |
| 系统单号 | 系统自动生成的运单编号 | 内部操作、日志、履约流转 |
| 转单号 | 快递号 / 承运商单号 | 承运商轨迹、客户查询、打单发货 |

注意：客户单号不是快递号；转单号才是快递号。

### 2.2 时间规则

系统页面展示的创建时间、操作时间、日志时间统一按北京时间显示，精确到秒，格式为：

`YYYY-MM-DD HH:mm:ss`

### 2.3 业务类型

顶部业务类型当前统一聚合为“专线”视角，用于承载快递、小包、专线的综合订单数据。后续如需拆分，可再恢复独立业务类型。

### 2.4 价格字段

报价查价模块中需要区分这些概念：

| 名称 | 含义 |
| --- | --- |
| 承运商 | UPS、DHL、FEDEX、专线等大类 |
| 代理商 | 报价来源，例如某个代理或价格表来源 |
| 承运路线 | 公司内部配置的业务路线名称 |
| 渠道报价表 / 真实渠道 | 真实报价渠道名称，来自价格表或代理接口 |
| 未绑定路线 | 有真实渠道，但没有绑定内部承运路线 |

业务员只需要看到可报价结果，不需要看到代理成本、加价规则、毛利等内部数据。管理员可以查看和维护内部成本与规则。

## 3. 角色与权限

系统按角色隔离一级菜单、二级功能、按钮和敏感字段。系统手册与页面均不展示账号密码，账号由管理员分配。

| 角色 | 定位 | 主要权限 |
| --- | --- | --- |
| 系统管理员 | 平台最高权限 | 全部员工端菜单、基础资料、财务、报价管理、系统设置、权限配置 |
| 客服 | 客户服务和问题跟进 | 运单查询、问题件、轨迹跟进、报价查询、基础资料读取 |
| 操作 | 仓库和履约作业 | 运单履约、收货打单、渠道排货、轨迹监控、问题件、基础资料读取 |
| 财务 | 账务和对账 | 财务结算、报价查询、统计报表、运单读取、基础资料读取 |
| 客户 | 客户自助入口 | 客户门户、本人运单、本人费用、本人问题件 |

权限边界：

- 客户登录后只进入客户门户，看不到员工端菜单。
- 操作角色不能进入系统设置，不能查看成本、加价、毛利等内部价格信息。
- 财务可以查看财务模块和对账能力，但不能修改系统权限。
- 管理员可以查看和维护报价表、代理加价规则、成本台账和系统权限。
- AI 接口要求登录后调用，并遵守当前角色的数据范围。

## 4. 页面结构

系统采用“左侧一级菜单 + 页面内二级功能菜单 + 右侧工作区”的结构。

一级菜单用于区分业务模块，例如“运单履约”“报价查价”“基础资料”。  
二级功能用于在同一个模块中切换具体能力，例如报价查价下的“查价”“代理加价规则”“价格表管理”。

这样做的目的：

- 避免一个页面一次性堆满所有功能。
- 让用户每次只聚焦一个工作区。
- 方便后续把每个二级功能逐步加深成完整闭环。

## 5. 运营工作台

运营工作台用于查看全局运营情况和重点风险。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 专线运单池 | 查看当前专线视角下的运单池、状态数量和重点运单 |
| AI 优先队列 | 查看 AI 识别出的高优先级待处理事项 |
| 产品地图 | 查看系统各模块能力分布和建设阶段 |
| 导入质检 | 查看导入数据的质量检查结果和异常提醒 |

常见用途：

- 管理员看整体运营压力。
- 客服快速定位异常、轨迹超时、客户咨询件。
- 操作查看待入库、待排货、待发货的任务量。
- 财务从运营数据追溯费用风险。

## 6. 运单履约

运单履约是出货订单的核心生命周期页面。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 履约阶段看板 | 查看订单状态池、表格、批量轨迹和单票履约操作 |
| AI 履约助手 | 识别问题件、缺转单号、轨迹超时等风险，并生成建议 |

### 6.1 核心状态

| 页面状态 | 系统状态 | 含义 |
| --- | --- | --- |
| 待审核 | DRAFT | 业务员新建出货订单后，等待审核 |
| 已入库 | WAITING_RECEIVE | 审核通过后进入入库/收货队列 |
| 待排货 | WAITING_SORT | 已收货，等待分配渠道或代理 |
| 待发货 | WAITING_DISPATCH | 已排货，等待确认出库 |
| 待上网 | WAITING_ONLINE | 已发货，等待承运商轨迹上网 |
| 待签收 | WAITING_SIGNED | 已上网运输中，等待签收 |
| 退货/滞留 | WAITING_RETURN / STUCK | 退货、滞留或异常流转 |
| 问题件 | PROBLEM | 需要人工处理的问题票 |
| 已签收 | SIGNED | 运输完成 |
| 已取消 | CANCELLED | 订单取消 |

### 6.2 新建出货订单

点击“新建出货订单”后填写订单信息。

表单字段包括：

- 客户名称
- 客户单号
- 系统单号
- 转单号，可为空，因为新建订单时可能还没有快递号
- 目的地
- 承运商
- 件数
- 应收计费重
- 代理计费重
- 备注

创建时间由系统自动补充。创建后订单进入“待审核”队列。

### 6.3 审核机制

订单创建后不能直接进入收货打单，需要先审核。

点击“审核”时会出现二次确认：

- 确认后：订单进入“已入库”队列，并同步到收货打单模块。
- 取消后：订单状态不变，不写操作日志，不显示审核成功。

### 6.4 单票操作

履约表格支持这些操作：

- 审核：把待审核订单推入已入库队列。
- 分配渠道：进入排货状态或分配渠道。
- 添加轨迹：手工补充最新轨迹。
- 标记退货：将订单转为退货/滞留类处理。
- 确认收货：确认货物到仓。
- 确认发货：确认出库。
- 填写转单号：补充快递号。
- 修改：人工修改最新轨迹、状态和转单号。
- 收款：登记收款金额和方式。
- 操作日志：查看该票生命周期操作记录。
- 删除：人工删除不需要或过期的订单。

### 6.5 收款信息

收款登记支持：

- 收款金额 USD
- 收款金额 CNY
- 收款方式：对公、对私、阿里店铺、外汇

金额 USD 和 CNY 可选填，至少按业务实际录入其中一种。未登记前金额和付款方式显示为“未知”。

### 6.6 操作日志

每票订单支持查看操作日志。日志包含：

- 操作时间
- 操作人员
- 操作动作
- 相关变化

例如：某员工修改了转单号、确认了收货、登记了收款，都会在该票日志中留下记录。

### 6.7 批量添加轨迹

点击“批量添加轨迹”后可导入 XLS / XLSX 表格。表格字段建议包括：

- 客户单号
- 日期
- 描述
- 位置

同一个客户单号可能存在多条轨迹，系统按该单号取日期最新的一条轨迹写入“最新轨迹”。一个表中包含多个单号时，按单号分别匹配更新。

## 7. 渠道排货

渠道排货用于从排货角度查看和处理同一批履约订单。它和“运单履约”共享订单数据，但操作入口应保持独立，不能互相误触发。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 履约阶段看板 | 从排货视角查看待排货、缺转单号、待发货等订单 |
| 模拟业务数据 | 查看排货相关测试数据 |
| 模块待办 | 查看排货侧待处理事项 |
| AI 赋能 | 生成渠道推荐、风险说明和成本倒挂解释 |
| 快捷动作 | 查看当前排货模块快捷操作 |

业务规则：

- 操作角色只能看到渠道大类，例如 DHL、UPS、FEDEX。
- 管理员、客服、财务可以看到更完整的渠道和代理信息。
- 排货结果应保留真实渠道、代理和内部路线信息，便于后续财务与统计。

## 8. 收货打单

收货打单承接审核通过后的订单，主要面向仓库作业。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| API 收货打单队列 | 查看待申请面单、待确认收货和 API 标签相关任务 |
| 文档覆盖样例 | 查看面单、标签、文档覆盖类示例数据 |

核心能力：

- 确认收货。
- 申请面单。
- 查看面单。
- 作废面单。
- 检查重复扫描和重量差异。
- 为后续打印套件、电子秤和 PDA 作业预留接口。

## 9. 轨迹监控

轨迹监控用于承运商轨迹同步、手工轨迹维护和客户可见轨迹管理。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 承运商任务 | 查看待同步、失败、重试中的承运商轨迹任务 |
| 最新轨迹 | 查看当前运单最新轨迹和异常更新状态 |

核心能力：

- 手工添加轨迹。
- 标记上网。
- 标记签收。
- 查看客户可见轨迹。
- 识别未上网和长时间未更新。
- 生成客户说明。

代理或承运商接口异常时，系统应明确显示错误状态，例如 Token 错误，避免业务员误以为只是无报价或无轨迹。

## 10. 问题件中心

问题件中心用于集中处理异常件。

核心能力：

- 新建问题件。
- 员工回复。
- 客户回复模拟。
- 关闭问题件。
- 关联运单。
- 控制客户可见状态。
- 查看 SLA 超时风险。
- AI 生成回复建议。

业务意义：

- 把异常从聊天记录沉淀为系统记录。
- 区分内部处理和客户可见内容。
- 让客服、操作、财务围绕同一票件协同。

## 11. 报价查价

报价查价用于根据报价表、重量、目的地和规则生成业务员报价。

二级功能：

| 二级功能 | 可见角色 | 作用 |
| --- | --- | --- |
| 查价 | 管理员、客服、操作、财务 | 输入货物信息并查询报价 |
| 代理加价规则 | 仅管理员 | 维护不同代理的业务员加价规则 |
| 价格表管理 | 仅管理员 | 上传、删除、备注和管理报价表 |
| 代理成本价台账 | 仅管理员 | 查看导入后的代理成本价明细 |

### 11.1 查价输入

查价表单支持：

- 品名
- 亚马逊代码
- 目的地
- 邮编
- 地址
- 数据/包装说明
- 实际重量 KG
- 方数 CBM
- 长、宽、高、件数
- 单件实重 KG

系统可根据 CBM 计算计费重。当前页面会显示自动计费重，方便用户确认。

### 11.2 查询结果

查询后展示：

- 业务员报价
- 推荐渠道
- 计费重
- 重量段
- 业务员单价
- 得出总价
- 最便宜 Top3
- 最快 Top3

命中多条报价时，系统会同时输出：

- 最便宜 Top3
- 物流速度最快 Top3

每条推荐结果保留自己的真实渠道名称，不会被内部路线合并覆盖。

### 11.3 权限差异

管理员可以看到：

- 代理成本价
- 代理加价
- 成本合计
- 毛利
- 代理加价规则
- 价格表管理
- 代理成本价台账

业务员、客服、操作等非管理员只看到：

- 推荐渠道
- 业务员单价
- 总报价
- Top3 推荐

非管理员不能看到成本、加价、毛利、价格表管理和成本台账。

### 11.4 价格表备注

管理员可在“价格表管理”中维护价格表备注。

例如：

`亚马逊卡派最长边 180CM-220CM，包税 +1.7 元/KG，不包税 +280 元/CBM`

该备注会应用到该价格表来源的报价结果中。报价推荐卡片只提示“有备注”，点击详情后查看完整备注和报价明细。

系统不需要自动抓取备注列，备注由管理员人工维护。

### 11.5 未绑定路线

当报价结果有真实渠道，但没有绑定内部承运路线时：

- 报价仍然展示。
- 承运路线显示“未绑定路线”。
- 页面以警告样式提醒需要维护渠道映射。
- 正式下单前应按业务规则确认或拦截。

## 12. 财务结算

财务结算用于处理费用、对账、收付款、核销和流水。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 应收费用 | 查看和生成客户应收费用 |
| 客户对账单 | 生成客户对账单并模拟确认 |
| 账户流水 | 查看客户账户余额变化和核销记录 |

核心能力：

- 运单产生应收/应付费用。
- 费用调整。
- 客户对账。
- 代理对账。
- 收款登记。
- 付款登记。
- 核销。
- 余额流水。

权限边界：

- 管理员和财务可以操作核销类能力。
- 客服和操作不能做财务核销。
- 客户只能查看本人费用、对账单和余额。

## 13. 统计报表

统计报表用于查看运营、财务和利润表现。

当前能力方向：

- 运单报表。
- 收货统计。
- 发货统计。
- 应收应付分析。
- 利润分析。
- 客户维度报表。
- 代理维度报表。
- AI 生成日报和异常趋势说明。

当前版本以模拟数据和展示闭环为主，后续接入真实数据库后可扩展为正式 BI 报表。

## 14. 基础资料

基础资料用于维护客户和代理的主数据。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 客户资料 | 维护客户编码、简称、全称、类型和业务员 |
| 代理资料 | 维护代理编码、简称、名称、状态和对接类型 |
| AI 资料助手 | 检查资料缺失、冲突和维护建议 |

### 14.1 客户资料

客户资料字段：

- 客户编码
- 客户简称
- 客户全称
- 客户类型
- 业务员

支持：

- 查询
- 重置
- 增加
- 修改
- 删除/停用
- 列表设置

### 14.2 代理资料

代理资料字段：

- 代理编码
- 代理简称
- 代理名称
- 状态
- 代理对接类型

支持：

- 查询
- 重置
- 增加
- 修改
- 删除/停用
- 列表设置

删除类操作按业务系统习惯优先做“停用”，不建议物理删除。

## 15. 系统设置

系统设置仅管理员使用。

二级功能：

| 二级功能 | 作用 |
| --- | --- |
| 员工账号管理 | 查看和维护员工角色、账号状态和数据范围 |
| 角色权限分配 | 配置角色可见菜单和能力范围 |
| 客户端角色权限 | 配置客户侧角色能力 |
| 权限安全区 | 查看权限风险和边界提醒 |
| AI 接口安全 | 检查 AI 调用是否受登录态和权限控制 |
| 高危操作审计 | 查看批量修改、发货、核销、权限修改等审计记录 |
| 系统基础配置 | 维护公司资料、模板、通知、轨迹规则和状态字典 |

系统设置原则：

- 管理员权限最大。
- 权限变更必须写入审计。
- 页面不展示账号密码。
- AI Key、接口密钥等敏感信息不能写入前端页面或手册。

## 16. 客户门户

客户登录后进入客户门户，不显示员工端菜单。

客户门户能力：

- 预报运单。
- 我的运单。
- 问题件。
- 价格查询。
- 偏远/邮编/黑名单查询。
- 对账单。
- 费用明细。
- 账户余额。
- 个人中心。

客户只能查看本人或所属客户公司的数据，不能访问员工基础资料、系统设置、成本价格和内部审计。

## 17. AI 助手

系统多处提供 AI 能力，统一通过后端 AI 接口调用。

典型场景：

- 运营工作台：生成优先处理队列。
- 运单履约：识别问题件、缺转单号、轨迹超时。
- 收货打单：识别重复扫描、重量差异、资料缺失。
- 渠道排货：推荐渠道，解释成本倒挂。
- 轨迹监控：解释未上网和未更新。
- 问题件中心：归类原因，生成回复建议。
- 报价查价：解释报价差异和推荐方案。
- 财务结算：解释费用差异和生成对账摘要。
- 系统设置：检查权限和配置风险。

AI 输出是辅助建议，不自动替代人工确认。发货、退货、核销、权限修改等高风险动作仍需人工点击确认，并写入日志或审计。

## 18. 推荐业务流程

### 18.1 员工端标准流程

1. 管理员维护基础资料和报价表。 
2. 业务员在运单履约中新建出货订单。
3. 管理员或有权限人员审核订单。
4. 审核通过后订单进入已入库队列，并同步到收货打单。
5. 仓库确认收货和打单。
6. 操作在渠道排货中分配渠道、代理和承运商。
7. 补齐转单号。
8. 确认发货。
9. 在轨迹监控中跟进上网、未更新和签收。
10. 异常票进入问题件中心。
11. 财务登记收款、生成对账、核销。
12. 统计报表查看运营和利润表现。

### 18.2 报价流程

1. 管理员在价格表管理中导入价格表。
2. 管理员维护价格表备注和代理加价规则。
3. 业务员在查价页输入目的地、重量、邮编、货物信息。
4. 系统输出业务员报价、推荐渠道、Top3 最便宜和 Top3 最快。
5. 管理员可查看成本、加价、毛利和价格表台账。
6. 非管理员只看到业务可用报价，不看到内部成本。

### 18.3 客户侧流程

1. 客户登录客户门户。
2. 创建预报或查看已有运单。
3. 查看轨迹和转单号。
4. 对问题件进行回复。
5. 查看费用明细、对账单和账户余额。

## 19. 当前版本边界

当前版本已经具备可操作的前端闭环和部分接口闭环，但仍有以下边界：

- 真实承运商 API 暂未正式接入。
- 打印套件、电子秤、PDA 暂未连接真实设备。
- 微信公众号客户入口待后续建设。
- 自动轨迹抓取目前以模拟/预留为主。
- 自动对账和欠费催收待后续接队列和定时任务。
- 部分模块仍使用本地 mock 或内存数据，后续接数据库后再完整持久化。
- 系统设置中的角色/菜单/按钮权限已经有页面和边界设计，完整 CRUD 需接数据库后继续落地。

## 20. 常见问题

### Q1：为什么新建订单后没有直接进入收货打单？

因为系统增加了审核机制。订单必须审核通过后才进入已入库队列，并同步到收货打单。

### Q2：为什么新建订单时转单号不是必填？

新建出货订单时通常还没有真实快递号，所以转单号允许为空。后续可在填写转单号或修改中补录。

### Q3：业务员为什么看不到成本和毛利？

成本、加价、毛利属于内部敏感数据，仅管理员可见。业务员只需要看到业务员报价、推荐渠道和总价。

### Q4：价格表备注从哪里维护？

由管理员在“报价查价 -> 价格表管理”中人工维护。系统不自动抓取备注列。

### Q5：为什么渠道显示不完整？

操作角色默认只看到渠道大类，避免暴露内部代理和具体渠道信息。管理员、客服、财务可以看到更完整的信息。

### Q6：操作日志有什么用？

操作日志记录单票生命周期中的关键动作，例如审核、修改转单号、确认收货、收款、删除等，便于追责和复盘。
