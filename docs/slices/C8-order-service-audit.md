# C8-order-service-audit

## 任务编号
C8-order-service-audit

## 服务目标
本卡焦点：C 批总销账。

本卡必须服务对应批次总目标：同一张订单从仓库货物录单，经过待审核、排货、待出库、出库、客服数据确认、转单号、状态池，最后由业务员确认签收。

## 来源依据
- docs/sunny-lifecycle-objective-audit.md 第 23 节 C 批订单客服开工卡。
- 本卡不是独立发挥，必须保留本批开工卡的全部字段、角色、日志、完成销账和不通过判定要求。

## 本任务边界
本卡只做“C 批总销账”相关的复用审计和最小补差。

对应批次边界：C 批承接 B 批仓库货物事实源，不能绕过仓库收货、理货、待出库；也不能跳过出库后的客服数据确认。

## 固定样本对象
客户 `9409`；组合号 `9409-KY-STOCK-075`；运单 `S-9409-001`；业务员账号；市场账号；仓库账号；客服账号；财务只读账号；管理员账号。

## 本卡必须覆盖的需求字段
录单、审核、排货、出库、客服双审核、转单号、状态池、问题件、签收的全链路证据。

## 对应批次完整开工要求
| 项 | 内容 |
| --- | --- |
| 本批要证明的目标 | 同一张订单从仓库货物录单，经过待审核、排货、待出库、出库、客服数据确认、转单号、状态池，最后由业务员确认签收。 |
| 本批必须完成的节点 | 从仓库货物录单、待审核、审核通过、市场排货、待出库衔接、出库后客服数据确认、业务数据审核、代理数据审核、转单号/面单、追踪显示控制、状态池、问题件挂载、业务员确认签收。 |
| 本批不做 | 水单到账、应收审核、业务成本审核、应付审核、待付款、已付款、代理账单核对、自动轨迹抓取、企业微信真实推送。 |

## 开工前现状审计清单
1. 当前已有页面。
2. 当前已有接口。
3. 当前已有数据库表/字段。
4. 当前已有状态枚举。
5. 当前已有权限点。
6. 当前已有审计 action。
7. 当前已有 e2e/unit 测试。
8. 哪些能力可以直接复用。
9. 哪些能力只需要补字段。
10. 哪些能力只需要补页面操作。
11. 哪些能力只需要补接口返回。
12. 哪些能力只需要补权限裁剪。
13. 哪些能力只需要补 audit log。
14. 哪些能力只需要补测试断言。
15. 哪些确实不存在，才允许新增。

## 优先复用清单
- 先复用已有页面、接口、表、字段、状态、权限、审计 action 和测试。
- 已有接口能表达的，不新建平行接口。
- 已有表能表达的，不新建平行表。
- 已有状态机能扩展的，不新建第二套状态机。
- 已有 RBAC 和 `AuditLog` 必须复用。
- 只有完成开工前复用审计并说明不能复用时，才允许最小新增。

## 允许的最小新增
- 只允许补齐本卡焦点无法由现有能力表达的最小字段、接口返回、页面操作、权限裁剪、audit log 或测试断言。
- 如认为必须新增表/接口/状态，先输出：现有能力是什么、为什么不能复用、新增最小范围、是否造成重复模型、如何和旧模型关联、如何迁移或兼容、如何用 9409 样本验证、如何避免维护两套逻辑。

## 字段矩阵
| 节点 | 必须字段 | 关键规则 | 本批验收 |
| --- | --- | --- | --- |
| 从仓库货物录单 | 客户编号、仓库包裹/组合号、件数、重量、尺寸、体积、目的地、收货人、业务员、业务渠道、货物摘要 | 录单应从仓库货物自动汇总，不逐件手填仓库已有重量尺寸 | `S-9409-001` 能反查 `9409-KY-STOCK-075` 来源 |
| 录单费用摘要 | 应收摘要、业务成本摘要、应付摘要权限占位 | 业务员可看应收和业务成本口径，不可见真实应付 | 业务员详情不返回应付和真实代理渠道 |
| 待审核 | 运单号、客户编号、业务员、货物摘要、费用摘要、审核人、审核时间、审核状态、驳回/恢复原因 | 审核通过后才可进入待排货；三天未审软删除/恢复按权限 | 未审核订单不能排货 |
| 市场排货 | 公司渠道、真实代理、代理渠道、真实应付、排货人、排货审核人、排货时间、排货状态 | 业务渠道不等于真实代理渠道；排货时间必填；业务员不可见真实代理渠道和真实应付 | 市场排货后进入仓库待出库 |
| 待出库衔接 | 运单号、客户编号、代理渠道、件数、重量、交接单信息、排货时间、待出库时间 | 仓库只读取出库所需字段，不看价格 | 仓库能看到待出库但看不到应收/应付/利润 |
| 出库后接收 | 出库时间、出库人、交接单号、客服接收状态 | 出库后必须进入客服数据确认，不得直接进入待离港 | 出库后订单停在客服数据确认池 |
| 客服业务数据审核 | 业务数据审核状态、审核人、审核时间、修改/反审核原因、差异反馈 | 业务数据审核和代理数据审核是两条记录，不用单一“已确认”替代 | 业务数据未审时不能转单号 |
| 客服代理数据审核 | 代理数据审核状态、审核人、审核时间、代理计费重、代理渠道、差异反馈 | 计费重差异要能反馈业务员 | 代理数据未审时不能转单号 |
| 转单号/面单 | 转单号、面单路径或图片、追踪网站、显示开关、填写人、填写时间 | 双审核完成后才能填转单号；追踪网站默认对业务员隐藏 | 业务员默认看不到追踪网站，客服可控制显示 |
| 状态池 | 待离港、已离港、已到港、已派送、已签收、状态时间、停留时长 | 状态池是客服运营池，不用自由状态文本替代 | 状态推进有原状态、新状态和时间 |
| 问题件 | 问题 id、问题类型、说明、处理人、状态、关联运单、原状态池 | 问题件是挂载，不能把订单从原状态池移走 | 问题件出现时，订单仍在原状态池可查 |
| 业务员确认签收 | 签收确认人、确认时间、确认备注、最终状态 | 业务员确认签收是本批最后节点 | 未经业务员确认不能算订单签收闭环 |

## 角色矩阵

| 市场/排货 | 待排货订单、真实代理、代理渠道、真实应付、排货时间、排货审核 | 水单、付款凭证、客服签收确认 | 市场能确认付款或替代客服签收 |
| 客服 | 出库后订单、业务数据审核、代理数据审核、转单号、面单、追踪显示、状态池、问题件 | 应付付款审批、代理银行付款操作 | 客服未双审核即可填转单号，或能确认付款 |
| 财务 | 订单和出库状态只读、费用来源只读 | 仓库出库动作、市场排货动作、客服签收动作 | 财务账号能替代客服确认状态或业务员签收 |
| 管理员 | 全部订单、状态、权限和日志 | 无业务隐藏 | 管理员无法按运单查完整动作日志 |

## 验收步骤
1. 按“开工前现状审计清单”先审计现有实现。
2. 证明本卡焦点“C 批总销账”能复用哪些已有页面、接口、表、状态、权限、日志和测试。
3. 只做允许的最小补差。
4. 用固定样本对象验数据证据、角色证据、日志证据和后端字段裁剪证据。
5. 更新 `.codex-state.md`，把下一张任务卡指向队列中的下一项。

## 不通过条件
| 情况 | 判定 |
| --- | --- |
| 录单没有绑定仓库货物来源 | 不通过 |
| 审核通过前能排货 | 不通过 |
| 出库后直接进入待离港，跳过客服数据确认 | 不通过 |
| 只有单一“已确认”状态，没有业务数据审核和代理数据审核 | 不通过 |
| 双审核未完成就能填转单号 | 不通过 |
| 追踪网站默认暴露给业务员 | 不通过 |
| 问题件把订单从原状态池移走 | 不通过 |
| 未经业务员确认就算已签收闭环 | 不通过 |
| 录单、审核、排货、客服审核、转单号、状态池、问题件、签收任一关键动作没有日志 | 不通过 |
