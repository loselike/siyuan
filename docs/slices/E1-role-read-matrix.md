# E1-role-read-matrix

## 任务编号
E1-role-read-matrix

## 服务目标
本卡焦点：角色读取验收矩阵。

本卡必须服务对应批次总目标：每个角色只看到自己该看的字段；每一步都有 actor、target、createdAt 和必要 before/after；同一客户、货、订单、费用能互相追溯。

## 来源依据
- docs/sunny-lifecycle-objective-audit.md 第 25 节 E 批权限追溯开工卡。
- 本卡不是独立发挥，必须保留本批开工卡的全部字段、角色、日志、完成销账和不通过判定要求。

## 本任务边界
本卡只做“角色读取验收矩阵”相关的复用审计和最小补差。

对应批次边界：E 批不新增业务流程，只验证 A-D 批的同一组样本在不同角色下是否按权限裁剪，并验证关键动作是否都有可追溯记录。

## 固定样本对象
客户 `9409`；组合号 `9409-KY-STOCK-075`；运单 `S-9409-001`；水单 `WR-9409-001`；付款申请 `PA-9409-001`；业务员、仓库、市场、客服、财务、管理员六类账号。

## 本卡必须覆盖的需求字段
业务员、仓库、市场、客服、财务、管理员读取同一对象时的返回和不返回字段。

## 对应批次完整开工要求
| 项 | 内容 |
| --- | --- |
| 本批要证明的目标 | 每个角色只看到自己该看的字段；每一步都有 actor、target、createdAt 和必要 before/after；同一客户、货、订单、费用能互相追溯。 |
| 本批必须完成的节点 | 同一对象多角色读取、敏感字段后端裁剪、越权操作拒绝、关键动作日志查询、对象互相追溯、图片/凭证关联业务对象。 |
| 本批不做 | 新增仓库、订单、财务业务节点；AI 自动核对；PDA 实时接口；企业微信真实推送；外部会计系统。 |

## 开工前现状审计清单
1. 当前已有页面。
2. 当前已有接口。
3. 当前已有数据库表/字段。
4. 当前已有状态枚举。
5. 当前已有权限点。
6. 当前已有审计 action。
7. 当前已有 e2e/unit 测试。
8. 哪些能力可以直接复用。
9. 哪些能力只需要补字段。
10. 哪些能力只需要补页面操作。
11. 哪些能力只需要补接口返回。
12. 哪些能力只需要补权限裁剪。
13. 哪些能力只需要补 audit log。
14. 哪些能力只需要补测试断言。
15. 哪些确实不存在，才允许新增。

## 优先复用清单
- 先复用已有页面、接口、表、字段、状态、权限、审计 action 和测试。
- 已有接口能表达的，不新建平行接口。
- 已有表能表达的，不新建平行表。
- 已有状态机能扩展的，不新建第二套状态机。
- 已有 RBAC 和 `AuditLog` 必须复用。
- 只有完成开工前复用审计并说明不能复用时，才允许最小新增。

## 允许的最小新增
- 只允许补齐本卡焦点无法由现有能力表达的最小字段、接口返回、页面操作、权限裁剪、audit log 或测试断言。
- 如认为必须新增表/接口/状态，先输出：现有能力是什么、为什么不能复用、新增最小范围、是否造成重复模型、如何和旧模型关联、如何迁移或兼容、如何用 9409 样本验证、如何避免维护两套逻辑。

| 范围 | 必须遵守 |
| --- | --- |

## 角色矩阵
| 角色 | 必须返回 | 必须不返回 | 不通过表现 |
| --- | --- | --- | --- |
| 业务员 | 自己客户、自己订单、业务渠道、应收状态、业务成本口径、客服状态、签收确认 | 真实代理渠道、真实应付、代理银行、待付款、已付款、他人客户、追踪网站默认链接 | 接口返回敏感字段，即使前端没显示也不通过 |
| 仓库 | 站点、件数、重量、尺寸、异常、理货、标签、交接单、出库状态 | 应收、业务成本、真实应付、利润、水单、付款、客户财务信息 | 仓库接口返回任何价格或付款字段 |
| 市场/排货 | 待排货、真实代理、代理渠道、真实应付、排货时间、排货审核 | 水单到账审核、付款申请、已付款确认、客服签收确认 | 市场能执行财务到账或付款动作 |
| 客服 | 业务数据审核、代理数据审核、转单号、追踪显示开关、状态池、问题件 | 应付付款审批、代理银行付款操作、水单匹配 | 客服能确认付款或绕过双审核填转单号 |
| 财务 | 水单、应收、业务成本、应付、待付款、已付款、凭证、代理银行 | 仓库收货/出库动作、市场排货审核、业务员签收 | 财务能替代仓库、市场或业务员完成非财务动作 |
| 管理员 | 全字段、全状态、全日志、权限配置 | 无业务隐藏 | 管理员无法按客户/货/单/水单/付款申请查完整链路 |

## 日志矩阵
| 日志类型 | 必须覆盖动作 | 必须字段 |
| --- | --- | --- |
| 基础资料日志 | 客户、代理、渠道、汇率、站点、用户组、用户名新增/修改/停用 | actor、target、createdAt、before/after |
| 仓库日志 | 收货、件重尺修正、异常、理货、标签、拆票、合票、交接单、出库 | actor、target、createdAt、包裹/组合号、状态前后 |
| 订单客服日志 | 录单、审核、排货、出库接收、业务数据审核、代理数据审核、转单号、状态池、问题件、签收 | actor、target、createdAt、运单号、状态前后、原因 |
| 财务日志 | 水单录入/到账/匹配、应收审核、业务成本审核、应付审核、付款申请、确认付款、凭证上传 | actor、target、createdAt、金额、币种、对象前后状态 |
| 权限日志 | 越权读取、越权修改、高危操作拒绝 | actor、target、createdAt、权限点、拒绝原因 |

## 验收步骤
1. 按“开工前现状审计清单”先审计现有实现。
2. 证明本卡焦点“角色读取验收矩阵”能复用哪些已有页面、接口、表、状态、权限、日志和测试。
3. 只做允许的最小补差。
4. 用固定样本对象验数据证据、角色证据、日志证据和后端字段裁剪证据。
5. 更新 `.codex-state.md`，把下一张任务卡指向队列中的下一项。

| 情况 | 判定 |
| --- | --- |
| 只验前端菜单，没有验后端返回字段 | 不通过 |

| 关键动作日志缺 actor、target、createdAt | 不通过 |
| 财务和权限动作缺 before/after 或必要 metadata | 不通过 |
