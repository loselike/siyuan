# D7-finance-audit

## 任务编号
D7-finance-audit

## 服务目标
本卡焦点：D 批总销账。

本卡必须服务对应批次总目标：同一客户水单到账后能匹配应收并审核；同一订单真实应付审核后生成待付款并确认已付款；财务动作都有凭证和日志。

## 来源依据
- docs/sunny-lifecycle-objective-audit.md 第 24 节 D 批财务付款开工卡。
- 本卡不是独立发挥，必须保留本批开工卡的全部字段、角色、日志、完成销账和不通过判定要求。

## 本任务边界
本卡只做“D 批总销账”相关的复用审计和最小补差。

对应批次边界：D 批承接 C 批订单事实和市场排货形成的真实应付，不做仓库收货、客服状态池、代理账单 AI 自动核对。

## 固定样本对象
客户 `9409`；运单 `S-9409-001`；水单 `WR-9409-001`；付款申请 `PA-9409-001`；业务员账号；市场账号；财务账号；管理员账号。

## 本卡必须覆盖的需求字段
水单、到账、应收匹配、应收审核、业务成本、应付审核、待付款、已付款、凭证的全链路证据。

## 对应批次完整开工要求
| 项 | 内容 |
| --- | --- |
| 本批要证明的目标 | 同一客户水单到账后能匹配应收并审核；同一订单真实应付审核后生成待付款并确认已付款；财务动作都有凭证和日志。 |
| 本批必须完成的节点 | 水单录入、确认到账、应收匹配、应收审核、业务成本审核、真实应付来源、应付审核、待付款、付款申请、已付款凭证、付款归档入口。 |
| 本批不做 | 仓库收货/理货/出库、客服转单号和状态池、代理账单 AI 自动核对、跨越月结自动匹配、外部会计系统。 |

## 开工前现状审计清单
1. 当前已有页面。
2. 当前已有接口。
3. 当前已有数据库表/字段。
4. 当前已有状态枚举。
5. 当前已有权限点。
6. 当前已有审计 action。
7. 当前已有 e2e/unit 测试。
8. 哪些能力可以直接复用。
9. 哪些能力只需要补字段。
10. 哪些能力只需要补页面操作。
11. 哪些能力只需要补接口返回。
12. 哪些能力只需要补权限裁剪。
13. 哪些能力只需要补 audit log。
14. 哪些能力只需要补测试断言。
15. 哪些确实不存在，才允许新增。

## 优先复用清单
- 先复用已有页面、接口、表、字段、状态、权限、审计 action 和测试。
- 已有接口能表达的，不新建平行接口。
- 已有表能表达的，不新建平行表。
- 已有状态机能扩展的，不新建第二套状态机。
- 已有 RBAC 和 `AuditLog` 必须复用。
- 只有完成开工前复用审计并说明不能复用时，才允许最小新增。

## 允许的最小新增
- 只允许补齐本卡焦点无法由现有能力表达的最小字段、接口返回、页面操作、权限裁剪、audit log 或测试断言。
- 如认为必须新增表/接口/状态，先输出：现有能力是什么、为什么不能复用、新增最小范围、是否造成重复模型、如何和旧模型关联、如何迁移或兼容、如何用 9409 样本验证、如何避免维护两套逻辑。

## 字段矩阵
| 财务节点 | 必须字段 | 关键规则 | 本批验收 |
| --- | --- | --- | --- |
| 水单录入 | 水单号、客户编号、币种、金额、付款编号、收款方式、凭证图片/路径、录入人、录入时间、到账状态 | 未到账水单不能抵扣应收；凭证必须关联水单对象 | `WR-9409-001` 未到账时不能匹配应收 |
| 确认到账 | 到账人、到账时间、到账金额、客户账户余额、到账备注 | 到账后才进入可匹配应收池 | 到账后客户账户余额增加，有日志 |
| 应收匹配 | 运单号、客户编号、水单号、匹配金额、币种、匹配人、匹配时间、余额变化 | 同币种匹配；不能超过水单余额 | `WR-9409-001` 匹配 `S-9409-001` 应收后余额正确变化 |
| 应收审核 | 应收费用 id、费用名称、金额、币种、水单匹配、审核人、审核时间、审核状态 | 审核后应收锁定；反审核按权限和下游状态控制 | 审核后无权限角色不能改金额 |
| 业务成本审核 | 业务成本费用 id、业务员、费用名称、计费重、单价、金额、审核人、审核时间 | 业务成本是业务员提成口径，不等于真实应付 | 业务员可看业务成本口径，但看不到真实应付 |
| 真实应付来源 | 运单号、真实代理、代理渠道、计费重、单价、金额、排货来源、供应商账单 | 应付来源来自排货/代理数据，不由业务员维护 | 应付能反查排货字段和代理 |
| 应付审核 | 应付费用 id、真实代理、代理渠道、金额、币种、审核人、审核时间、审核状态 | 审核后才能生成待付款；业务员不可见应付 | 应付未审核时不会出现在待付款 |
| 待付款 | 付款申请号、代理、银行账号、币种、金额、关联应付、申请人、申请时间、状态 | 按代理、银行账号、币种分组；不得跨代理/跨银行/跨币种混付 | `PA-9409-001` 只包含同一代理、银行和币种 |
| 已付款 | 付款申请号、付款时间、付款人、付款金额、付款对象、付款凭证、核销状态 | 付款凭证必须挂付款记录，不是孤立图片 | 已付款详情能打开凭证并反查付款申请 |
| 付款归档入口 | 已付款记录、关联应付、关联运单、代理、凭证、归档时间 | 归档不等于删除；后续代理账单核对要能读取 | 已付款可被代理账单核对入口引用 |

## 角色矩阵
| 角色 | 必须可见 | 必须隐藏 | 不通过表现 |
| --- | --- | --- | --- |
| 业务员 | 自己客户应收状态、业务成本口径、必要的收款状态 | 真实应付、待付款、已付款、代理银行、付款凭证、他人客户水单 | 业务员详情返回真实应付、代理银行或付款凭证 |
| 市场/排货 | 排货形成的真实应付来源和代理渠道 | 水单到账审核、付款申请、已付款确认 | 市场能确认水单到账或确认付款 |
| 财务 | 水单、应收、业务成本、应付、待付款、已付款、凭证、代理银行 | 仓库作业动作、客服签收动作 | 财务能替代仓库出库或业务员签收 |
| 客服 | 必要订单付款状态只读 | 水单匹配、应收审核、应付审核、确认付款 | 客服能审核应收或确认付款 |
| 仓库 | 不作为财务操作角色 | 全部水单、应收、业务成本、应付、付款、凭证 | 仓库账号能访问付款或水单明细 |
| 管理员 | 全部财务数据、权限和日志 | 无业务隐藏 | 管理员无法按水单/付款申请查日志 |

## 验收步骤
1. 按“开工前现状审计清单”先审计现有实现。
2. 证明本卡焦点“D 批总销账”能复用哪些已有页面、接口、表、状态、权限、日志和测试。
3. 只做允许的最小补差。
4. 用固定样本对象验数据证据、角色证据、日志证据和后端字段裁剪证据。
5. 更新 `.codex-state.md`，把下一张任务卡指向队列中的下一项。

## 不通过条件
| 情况 | 判定 |
| --- | --- |
| 未到账水单可以抵扣应收 | 不通过 |
| 跨币种直接匹配水单和应收 | 不通过 |
| 水单余额变化无法反查应收 | 不通过 |
| 应收审核后无权限仍可改金额 | 不通过 |
| 业务成本被当成真实应付 | 不通过 |
| 应付未审核就生成待付款 | 不通过 |
| 待付款跨代理、跨银行或跨币种混付 | 不通过 |
| 付款凭证没有关联付款记录 | 不通过 |
| 业务员能看到真实应付、代理银行、待付款或已付款 | 不通过 |
| 水单、应收、业务成本、应付、待付款、已付款任一关键动作没有日志 | 不通过 |
