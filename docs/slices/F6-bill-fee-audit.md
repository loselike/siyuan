# F6-bill-fee-audit

## 任务编号
F6-bill-fee-audit

## 服务目标
本卡焦点：F 批总销账。

本卡必须服务对应批次总目标：代理账单、杂费、跨越账单能人工进入 Sunny，并能关联代理、订单、应付、付款和差异日志。

## 来源依据
- docs/sunny-lifecycle-objective-audit.md 第 26 节 F 批账单杂费开工卡。
- 本卡不是独立发挥，必须保留本批开工卡的全部字段、角色、日志、完成销账和不通过判定要求。

## 本任务边界
本卡只做“F 批总销账”相关的复用审计和最小补差。

对应批次边界：F 批是第一阶段的财务扩展闭环，只做代理账单人工导入/核对、差异处理、杂费归属、跨越账单人工入口。

## 固定样本对象
运单 `S-9409-001`；付款申请 `PA-9409-001`；代理；代理账单号；杂费记录；财务账号；管理员账号。

## 本卡必须覆盖的需求字段
代理账单、账单明细、应付/付款关联、差异、杂费、跨越账单、核对结果的全链路证据。

## 对应批次完整开工要求
| 项 | 内容 |
| --- | --- |
| 本批要证明的目标 | 代理账单、杂费、跨越账单能人工进入 Sunny，并能关联代理、订单、应付、付款和差异日志。 |
| 本批必须完成的节点 | 代理账单人工导入、账单明细核对、应付/付款关联、差异标记、差异处理、杂费录入、杂费归属、跨越账单人工入口、账单核对日志。 |
| 本批不做 | AI 自动核对、AI 价格表、跨越月结自动匹配、外部会计系统、杂费批量自动识别、自动轨迹抓取。 |

## 开工前现状审计清单
1. 当前已有页面。
2. 当前已有接口。
3. 当前已有数据库表/字段。
4. 当前已有状态枚举。
5. 当前已有权限点。
6. 当前已有审计 action。
7. 当前已有 e2e/unit 测试。
8. 哪些能力可以直接复用。
9. 哪些能力只需要补字段。
10. 哪些能力只需要补页面操作。
11. 哪些能力只需要补接口返回。
12. 哪些能力只需要补权限裁剪。
13. 哪些能力只需要补 audit log。
14. 哪些能力只需要补测试断言。
15. 哪些确实不存在，才允许新增。

## 优先复用清单
- 先复用已有页面、接口、表、字段、状态、权限、审计 action 和测试。
- 已有接口能表达的，不新建平行接口。
- 已有表能表达的，不新建平行表。
- 已有状态机能扩展的，不新建第二套状态机。
- 已有 RBAC 和 `AuditLog` 必须复用。
- 只有完成开工前复用审计并说明不能复用时，才允许最小新增。

## 允许的最小新增
- 只允许补齐本卡焦点无法由现有能力表达的最小字段、接口返回、页面操作、权限裁剪、audit log 或测试断言。
- 如认为必须新增表/接口/状态，先输出：现有能力是什么、为什么不能复用、新增最小范围、是否造成重复模型、如何和旧模型关联、如何迁移或兼容、如何用 9409 样本验证、如何避免维护两套逻辑。

## 字段矩阵
| 节点 | 必须字段 | 关键规则 | 本批验收 |
| --- | --- | --- | --- |
| 代理账单导入 | 账单号、代理、账单日期、币种、账单金额、明细文件/图片、导入人、导入时间、状态 | 第一阶段人工导入；文件必须关联账单对象 | 账单能按代理和账单号查询 |
| 账单明细 | 运单号、转单号、代理渠道、计费重、单价、金额、币种、备注 | 明细要能关联 Sunny 里的应付费用或标记未匹配 | `S-9409-001` 明细能匹配应付 |
| 应付/付款关联 | 应付费用 id、付款申请号、已付款记录、账单明细 id | 代理账单核对应付和付款，不直接替代应付审核 | `PA-9409-001` 能从账单核对页反查 |
| 差异标记 | 差异类型、差异金额、差异原因、处理状态、处理人、处理时间 | 差异不能直接静默覆盖应付金额 | 差异有处理状态和日志 |
| 杂费录入 | 杂费类型、金额、币种、代理/客户/订单归属、发生日期、凭证、备注 | 杂费未来要能进入业务成本和应付；第一阶段先保留归属入口 | 杂费能挂客户、订单或代理 |
| 跨越账单入口 | 跨越账单号、客户/订单、金额、币种、账单日期、状态、文件 | 跨越月结自动匹配后置；第一阶段人工登记和关联 | 跨越账单可人工关联订单 |
| 核对结果 | 已匹配、差异待处理、差异已处理、已归档 | 归档不等于删除；后续可追溯 | 核对状态能按账单号查看历史 |

## 角色矩阵
| 角色 | 必须可见 | 必须隐藏 | 不通过表现 |
| --- | --- | --- | --- |
| 财务 | 代理账单、应付、付款、杂费、差异、凭证、跨越账单人工入口 | 仓库作业动作、客服签收动作 | 财务能替代仓库或客服业务动作 |
| 管理员 | 全部账单、杂费、差异、权限和日志 | 无业务隐藏 | 管理员无法查账单核对日志 |
| 市场/排货 | 与自己排货相关的代理/渠道差异只读或反馈 | 水单、付款确认、代理银行付款操作 | 市场能确认付款或归档账单 |
| 业务员 | 自己订单相关的杂费结果或差异反馈 | 真实应付、代理银行、代理账单完整明细、付款凭证 | 业务员看到完整代理账单或真实应付 |
| 仓库 | 不作为账单杂费操作角色 | 代理账单、杂费、应付、付款、凭证 | 仓库能访问账单核对页 |
| 客服 | 必要差异反馈只读 | 账单归档、付款确认、代理银行 | 客服能归档账单或确认付款 |

## 验收步骤
1. 按“开工前现状审计清单”先审计现有实现。
2. 证明本卡焦点“F 批总销账”能复用哪些已有页面、接口、表、状态、权限、日志和测试。
3. 只做允许的最小补差。
4. 用固定样本对象验数据证据、角色证据、日志证据和后端字段裁剪证据。
5. 更新 `.codex-state.md`，把下一张任务卡指向队列中的下一项。

## 不通过条件
| 情况 | 判定 |
| --- | --- |
| 代理账单文件孤立保存，不能关联代理账单号 | 不通过 |
| 账单明细无法关联 Sunny 应付或标记未匹配 | 不通过 |
| 差异直接覆盖应付金额，没有差异记录 | 不通过 |
| 杂费没有客户/订单/代理归属对象 | 不通过 |

| 业务员看到完整代理账单、真实应付或代理银行 | 不通过 |
| 账单导入、匹配、差异、杂费、归档任一关键动作没有日志 | 不通过 |
| 把 AI 自动核对当作第一阶段完成条件 | 不通过 |
