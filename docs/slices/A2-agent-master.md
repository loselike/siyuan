# A2-agent-master

## 任务编号
A2-agent-master

## 服务目标
本卡焦点：代理资料。

本卡必须服务对应批次总目标：为五条目标建立统一主数据：客户编号、站点、业务员归属、代理、渠道、角色、日志入口。

## 来源依据
- docs/sunny-lifecycle-objective-audit.md 第 21 节 A 批基础资料开工卡。
- 本卡不是独立发挥，必须保留本批开工卡的全部字段、角色、日志、完成销账和不通过判定要求。

## 本任务边界
本卡只做“代理资料”相关的复用审计和最小补差。

对应批次边界：A 批只解决主数据、角色和日志入口，不做仓库收货、订单录单、财务付款的业务流程。

## 固定样本对象
客户 `9409`；业务员账号；仓库账号；市场账号；客服账号；财务账号；管理员账号。

## 本卡必须覆盖的需求字段
代理编码、代理简称、详细公司名、仓库地址、联系人、银行账号、发票模板、状态。

## 对应批次完整开工要求
| 项 | 内容 |
| --- | --- |
| 本批要证明的目标 | 为五条目标建立统一主数据：客户编号、站点、业务员归属、代理、渠道、角色、日志入口。 |
| 本批必须完成的节点 | 客户资料、代理资料、代理渠道、公司渠道、渠道类别、偏远、汇率、站点、用户组、用户名、操作日志入口。 |
| 本批不做 | 今日收货、在仓、理货、录单、排货、客服数据确认、财务付款、代理账单核对、AI/PDA/企业微信真实推送。 |

## 开工前现状审计清单
1. 当前已有页面。
2. 当前已有接口。
3. 当前已有数据库表/字段。
4. 当前已有状态枚举。
5. 当前已有权限点。
6. 当前已有审计 action。
7. 当前已有 e2e/unit 测试。
8. 哪些能力可以直接复用。
9. 哪些能力只需要补字段。
10. 哪些能力只需要补页面操作。
11. 哪些能力只需要补接口返回。
12. 哪些能力只需要补权限裁剪。
13. 哪些能力只需要补 audit log。
14. 哪些能力只需要补测试断言。
15. 哪些确实不存在，才允许新增。

## 优先复用清单
- 先复用已有页面、接口、表、字段、状态、权限、审计 action 和测试。
- 已有接口能表达的，不新建平行接口。
- 已有表能表达的，不新建平行表。
- 已有状态机能扩展的，不新建第二套状态机。
- 已有 RBAC 和 `AuditLog` 必须复用。
- 只有完成开工前复用审计并说明不能复用时，才允许最小新增。

## 允许的最小新增
- 只允许补齐本卡焦点无法由现有能力表达的最小字段、接口返回、页面操作、权限裁剪、audit log 或测试断言。
- 如认为必须新增表/接口/状态，先输出：现有能力是什么、为什么不能复用、新增最小范围、是否造成重复模型、如何和旧模型关联、如何迁移或兼容、如何用 9409 样本验证、如何避免维护两套逻辑。

## 字段矩阵
| 节点 | 必须字段 | 关键规则 | 本批验收 |
| --- | --- | --- | --- |
| 客户资料 | 客户编号、客户名称、业务员、联系方式、收货人一/二/三/四、结算信息、状态 | 客户编号是主识别字段，客户名称只辅助显示；收货人最多四组 | 客户 `9409` 可新增/修改/停用；后续仓库和录单都用客户编号引用 |
| 代理资料 | 代理编码、代理简称、详细公司名、仓库地址、联系人、银行账号、发票模板、状态 | 代理银行账号挂代理资料；发票模板跟代理/渠道绑定 | 财务和管理员可见银行；业务员不可见代理资料 |
| 代理渠道 | 代理、渠道名称、状态 | 代理渠道不是公司渠道；用于真实代理排货和应付 | 市场/财务可读；业务员默认隐藏 |
| 公司渠道 | 业务类型、渠道类别、渠道名称、承运商、除材积、多件重量计算方式、进位规则、大货起始重量、偏远规则、状态 | 保留重量进位规则；公司渠道不等于真实代理渠道 | 业务员可选业务渠道但不看真实代理渠道；市场可维护排货所需渠道 |
| 渠道类别 | 类别名称、状态 | 给公司渠道分类使用 | 启用类别可被公司渠道选择；停用类别不用于新建 |
| 偏远 | 国家/地区、邮编或区域、渠道、附加规则、状态 | 供公司渠道偏远规则引用 | 偏远规则可查、可停用、有日志 |
| 汇率 | 币种、汇率、启用日期、状态 | 汇率按历史时间匹配，不能只用当前值覆盖历史 | RMB/USD 等币种可维护；修改有日志 |
| 站点 | 站点名称、站点代码、状态、默认归属 | 仓库收货和在仓必须能归站点 | 仓库账号可按站点处理；业务员不看无关站点 |
| 用户组 | 角色名称、权限范围、状态 | 后端字段裁剪是事实源，前端隐藏只是辅助 | 业务员、仓库、市场、客服、财务、管理员角色存在 |
| 用户名 | 账号、姓名、用户组、业务员归属、站点归属、状态 | 后续样本必须能用不同角色账号验收 | 六类账号可登录或作为验收角色存在 |
| 操作日志 | 动作、操作人、对象、时间、before/after、metadata | 关键资料变更必须可追溯 | 新增/修改/停用客户、代理、渠道、用户时能查日志 |

## 状态流转矩阵
| 范围 | 必须遵守 |
| --- | --- |
| 本卡焦点 | 不允许绕过上游节点直接造完成态；状态必须能被下游读取。 |
| 对应批次 | 严格按 `sunny-lifecycle-objective-audit.md` 中本批开工卡的节点顺序推进。 |
| 全阶段 | A -> B -> C -> D -> E -> F 连续执行；历史落地只作为复用审计事实，不作为跳过依据。 |

## 角色矩阵
| 角色 | 必须可见 | 必须隐藏 | 不通过表现 |
| --- | --- | --- | --- |
| 业务员 | 自己客户资料、业务渠道基础选项、自己相关状态 | 代理资料、代理银行、真实代理渠道、真实应付、他人客户 | 业务员能打开代理资料或看到代理银行 |
| 仓库 | 站点、客户编号识别所需字段、仓库后续作业所需客户信息 | 应收、业务成本、真实应付、利润、水单、付款 | 仓库账号在基础资料里看到价格或财务字段 |
| 市场/排货 | 公司渠道、代理资料必要信息、代理渠道 | 水单到账、付款凭证、客户财务审核动作 | 市场账号可确认水单到账或付款 |
| 客服 | 客户编号、订单后续客服所需联系信息、渠道/代理只读信息 | 付款审批、代理银行付款操作 | 客服账号能做财务付款动作 |
| 财务 | 客户结算资料、代理银行、汇率、财务相关资料 | 仓库作业动作、市场排货审核动作 | 财务账号能替代仓库收货或市场排货 |
| 管理员 | 全部资料和日志 | 无业务隐藏 | 管理员无法查看资料变更日志 |

## 验收步骤
1. 按“开工前现状审计清单”先审计现有实现。
2. 证明本卡焦点“代理资料”能复用哪些已有页面、接口、表、状态、权限、日志和测试。
3. 只做允许的最小补差。
4. 用固定样本对象验数据证据、角色证据、日志证据和后端字段裁剪证据。
5. 更新 `.codex-state.md`，把下一张任务卡指向队列中的下一项。

## 不通过条件
| 情况 | 判定 |
| --- | --- |
| 客户资料没有客户编号主键口径 | 不通过 |
| 业务员能看到代理银行、真实代理渠道或真实应付 | 不通过 |
| 仓库能看到价格、利润、水单或付款 | 不通过 |
| 资料新增/修改/停用没有日志 | 不通过 |
| 没有六类角色账号或用户组 | 不通过 |
| 汇率只有当前值，没有历史生效口径 | 不通过 |
