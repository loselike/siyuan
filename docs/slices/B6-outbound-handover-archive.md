# B6-outbound-handover-archive

## 任务编号
B6-outbound-handover-archive

## 服务目标
本卡焦点：待出库、代理交接单、出库归档。

本卡必须服务对应批次总目标：货能从仓库今日收货走到出库归档；仓库和业务员看到各自该看的货物字段；仓库动作有追溯记录。

## 来源依据
- docs/sunny-lifecycle-objective-audit.md 第 22 节 B 批仓库货物开工卡。
- 本卡不是独立发挥，必须保留本批开工卡的全部字段、角色、日志、完成销账和不通过判定要求。

## 本任务边界
本卡只做“待出库、代理交接单、出库归档”相关的复用审计和最小补差。

对应批次边界：B 批只解决第一条主线的仓库事实源：货从客户/工厂来，到仓库收货、在仓、理货、标签、待出库、出库归档。B 批不做完整录单、客服、财务付款，但要给后续 C/D 批提供真实货物输入。

## 固定样本对象
客户 `9409`；组合号 `9409-KY-STOCK-075`；站点；仓库账号；业务员账号；管理员账号。

## 本卡必须覆盖的需求字段
运单号或出库单号、代理渠道、交接单号、件数、重量、出库人、交接时间、出库时间、归档状态。

## 对应批次完整开工要求
| 项 | 内容 |
| --- | --- |
| 本批要证明的目标 | 货能从仓库今日收货走到出库归档；仓库和业务员看到各自该看的货物字段；仓库动作有追溯记录。 |
| 本批必须完成的节点 | 入库标签识别、今日收货、在仓数据、未完成理货、已完成理货、理货后标签、拆票/合票、待出库、代理交接单、出库归档。 |
| 本批不做 | 完整录单审核、客服数据确认、转单号、状态池签收、水单应收、应付付款、代理账单核对、PDA 实时接口。 |

## 开工前现状审计清单
1. 当前已有页面。
2. 当前已有接口。
3. 当前已有数据库表/字段。
4. 当前已有状态枚举。
5. 当前已有权限点。
6. 当前已有审计 action。
7. 当前已有 e2e/unit 测试。
8. 哪些能力可以直接复用。
9. 哪些能力只需要补字段。
10. 哪些能力只需要补页面操作。
11. 哪些能力只需要补接口返回。
12. 哪些能力只需要补权限裁剪。
13. 哪些能力只需要补 audit log。
14. 哪些能力只需要补测试断言。
15. 哪些确实不存在，才允许新增。

## 优先复用清单
- 先复用已有页面、接口、表、字段、状态、权限、审计 action 和测试。
- 已有接口能表达的，不新建平行接口。
- 已有表能表达的，不新建平行表。
- 已有状态机能扩展的，不新建第二套状态机。
- 已有 RBAC 和 `AuditLog` 必须复用。
- 只有完成开工前复用审计并说明不能复用时，才允许最小新增。

## 允许的最小新增
- 只允许补齐本卡焦点无法由现有能力表达的最小字段、接口返回、页面操作、权限裁剪、audit log 或测试断言。
- 如认为必须新增表/接口/状态，先输出：现有能力是什么、为什么不能复用、新增最小范围、是否造成重复模型、如何和旧模型关联、如何迁移或兼容、如何用 9409 样本验证、如何避免维护两套逻辑。

## 字段矩阵
| 仓库节点 | 必须字段 | 关键规则 | 本批验收 |
| --- | --- | --- | --- |
| 入库标签识别 | 外部标签号、客户编号、客户单号、快递单号、件数、重量、尺寸、日期、二维码或条码内容 | Sunny 识别外部标签，不把入库标签当系统生成标签 | 标签信息能进入今日收货；无法识别时进入异常 |
| 今日收货 | 客户编号、客户单号、快递单号、站点、件数、重量、长宽高、6000 材积、5000 材积、扫描/导入时间、异常、备注 | 仓库机器默认 6000；系统补算 5000；收货是仓库包裹事实，不是运单 `receiveShipment` | 同一票货在今日收货可查；修改件重尺有日志 |
| 在仓数据 | 仓库包裹号、组合号、客户编号、件数、重量、尺寸、体积、入仓时间、站点、业务员、异常、出库状态 | 只显示未出库货；出库后默认移出在仓但可归档查询 | `9409-KY-STOCK-075` 在仓可查；业务员只看自己货 |
| 未完成理货 | 理货任务号、仓库包裹号、理货需求、原始件数/重量/尺寸、处理人、创建时间 | 合票不能替代理货完成 | 在仓货能进入未完成理货 |
| 已完成理货 | 完成时间、处理人、理货结果、理货后件数/重量/尺寸、原始数据引用 | 原始数据不能被覆盖；理货结果必须可追溯 | 完成后进入已完成理货，原始和理货后数据都可查 |
| 理货后标签 | 标签号、二维码内容、客户编号、日期、件数、关联仓库包裹、打印/下载状态 | 标签号、二维码、日期、件数按 Excel 图片落地；生成/重打/作废有日志 | 标签可打印/下载；标签号能反查来源包裹 |
| 拆票 | 源包裹号、子包裹号、拆分件数、拆分重量、拆分体积、操作人、操作时间 | 子包裹和源包裹必须互相追溯 | 源包裹拆出子包裹后，源/子关系可查 |
| 合票 | 合票批次、来源包裹列表、合计件数、重量、体积、客户编号、操作人、操作时间 | 合票用于后续录单输入，但不等于理货完成 | 合票批次能反查所有来源包裹 |
| 待出库 | 运单号或出库单号、客户编号、代理渠道、件数、重量、交接单信息、排货时间、待出库时间 | 仓库只能看出库所需字段，不看价格 | 排货后货物进入待出库；仓库看不到应收/应付/利润 |
| 代理交接单 | 交接单号、代理/渠道、运单/包裹、件数、重量、出库人、交接时间 | 交接单字段按 `仓库流程(1).xlsx`，不自由发挥 | 可打印/下载；交接单能关联出库记录 |
| 出库归档 | 出库时间、出库人、出库包裹、交接单号、归档状态、后续客服接收状态 | 出库后进入客服数据确认；从在仓消失但归档必须可查 | 出库后在仓默认不显示，出库归档能查到 |

## 验收步骤
1. 按“开工前现状审计清单”先审计现有实现。
2. 证明本卡焦点“待出库、代理交接单、出库归档”能复用哪些已有页面、接口、表、状态、权限、日志和测试。
3. 只做允许的最小补差。
4. 用固定样本对象验数据证据、角色证据、日志证据和后端字段裁剪证据。
5. 更新 `.codex-state.md`，把下一张任务卡指向队列中的下一项。

## 不通过条件
| 情况 | 判定 |
| --- | --- |
| 用运单 `receiveShipment` 代替仓库今日收货 | 不通过 |
| 今日收货能查，但在仓查不到同一票货 | 不通过 |
| 完成理货后没有理货后标签 | 不通过 |
| 出库后从在仓消失，但出库归档查不到 | 不通过 |
| 仓库能看到应收、应付、利润、水单或付款 | 不通过 |
| 业务员能看到他人货或全部仓库货 | 不通过 |
| 收货、理货、标签、出库任一关键动作没有日志 | 不通过 |
| 交接单字段不按 Excel sheet 落地 | 不通过 |
