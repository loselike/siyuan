# 客服面单上传、版本、作废与审计验收

## 1. 业务目标
保证每票面单可上传/粘贴、预览、替换和作废，并能追溯当前有效版本。

## 2. 使用角色
客服上传和作废；仓库按出库职责查看/打印；业务员按权限只读；客户默认不看内部面单；其他角色不得修改。

## 3. 用户流程
客服在转单号/待离港行点击上传面单→选择或粘贴图片/PDF→预览确认→生成新版本→列表显示当前有效面单；作废要求原因并回到无有效面单状态。

## 4. 业务规则
- 文件类型、大小、内容签名和安全存储校验；禁止仅信扩展名。
- 同票允许多版本但仅一个当前有效；替换不删除旧文件和审计。
- 上传、预览、下载、作废校验对象归属与权限；错误不泄露存储路径。
- 重复上传同一文件可幂等识别或明确产生新版本。

## 5. 不做范围
不生成承运商电子面单；不 OCR；不接外部对象存储迁移；不发布 47。

## 6. 工程落地点
ShipmentLabel、上传 controller、安全校验、CustomerServicePage/VoucherImageInput 可复用能力、下载鉴权、审计和 Web/API 测试。

## 7. 验收标准
- 图片/PDF 上传或粘贴后可预览，刷新仍存在。
- 替换/作废后当前版本正确，旧版本可审计但不作为当前使用。
- 非授权角色无法上传、作废或猜 URL 下载。
- 非法 MIME、超限、损坏文件被拒绝且不落脏记录。

## 9. 风险与待确认
