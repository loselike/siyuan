# 2026-07-07-business-order-entry-hide-payable-cost.md

## 1. 业务目标

业务账号在 `业务管理 -> 录单` 时不再看到或录入 `应付费用/出货成本`，只保留业务需要填写的客户应收与业务成本，避免业务权限触达代理应付成本。

## 2. 使用角色

- 业务员 / 业务角色组：录单时只能看到和维护客户应收、业务成本；不能看到 `应付费用` 区块、`出货成本` 默认行、代理应付、付款编号。
- 管理员：可继续按权限查看和维护完整费用信息。
- 财务：可继续在财务模块维护应收、业务成本、应付审核。
- 仓库/客户：不参与本卡；不能访问内部录单应付费用。

## 3. 用户流程

1. 业务员进入 `业务管理 -> 录单`。
2. 页面只展示订单基础信息、仓库货物、应收费用、业务成本。
3. 页面不展示 `应付费用` 卡片，不出现默认 `出货成本` 行，也不出现 `新增项目`、币种、计费重、出货成本单价、总金额、付款编号等应付相关字段。
4. 业务员点击 `保存草稿` 或 `提交审核` 时，请求体不得携带应付费用。
5. 管理员/财务进入同一录单能力时，如现有权限允许，可继续看到应付费用。
6. 后端即使收到业务账号提交的应付费用，也必须忽略或拒绝，不能落库。

## 4. 业务规则

- 权限边界：业务员、业务角色组不能查看、录入、提交、修改代理应付费用。
- 前端显隐：业务账号隐藏整个 `应付费用` 区块，而不是只禁用输入框。
- 后端裁剪：业务账号提交的 `payables` 必须不落库；不能只依赖前端隐藏。
- 费用口径：业务录单提交审核仍要求应收费用和业务成本完整；不要求应付费用。
- 财务后续：代理应付费用由市场排货或财务/管理员后续流程产生和审核，本卡不改变财务应付审核口径。
- 审计要求：本卡不新增业务动作；如后端拒绝越权应付提交，可记录权限拒绝审计。
- 敏感字段：业务账号不得看到代理、应付成本单价、应付总金额、付款编号、利润等敏感字段。

## 5. 不做范围

- 不改应收费用和业务成本录入。
- 不改待审核运单列表字段。
- 不改市场排货生成应付费用逻辑。
- 不改财务应付审核页面。
- 不改数据库结构。
- 不发布 47。
- 不修复无关仓库类型错误。

## 6. 工程落地点

- Web：`apps/web/src/modules/finance/entry/FinanceEntryPage.tsx` 根据角色隐藏 `应付费用` 区块，并确保业务账号提交 `payables: []`。
- API：`POST /api/shipments/order-entry`、`PUT /api/shipments/:id/order-entry-draft` 后端继续校验业务账号不能落应付费用。
- Shared：一般不需要改 DTO；如有权限类型缺口再补。
- 测试：补 Web 测试覆盖业务账号看不到 `应付费用/出货成本`；补 API 测试覆盖业务账号提交 payables 不落库或返回禁止。

## 7. 验收标准

- 验收 1：业务账号进入录单页面，看不到 `应付费用` 标题。
- 验收 2：业务账号录单页面看不到默认 `出货成本` 行。
- 验收 3：业务账号提交录单时，即使前端状态里存在 payables，也不会创建应付费用。
- 验收 4：管理员/财务按现有权限仍可看到应付费用区块。
- 验收 5：提交审核仍只校验应收费用、业务成本和订单必填字段，不要求应付费用。
- 验收 6：业务账号无法通过接口越权落库代理应付、付款编号或应付敏感字段。
