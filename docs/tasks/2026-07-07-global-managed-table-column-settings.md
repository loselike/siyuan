# 2026-07-07-global-managed-table-column-settings.md

## 1. 业务目标

为 Sunny 后台所有类似业务表格统一提供列顺序调整、字段显示/隐藏、列宽拖拽能力，让用户可以按自己的岗位习惯配置表格视图，并在本卡内完成从通用能力到全系统推广的闭环。

## 2. 使用角色

- 管理员：可在所有有权限进入的后台模块使用列设置和列宽拖拽。
- 业务员、仓库、市场、客服、财务：只可在自己有权限进入的模块使用。
- 客户：本卡不覆盖客户门户，除非代码盘点确认其表格复用后台通用组件且无权限风险。
- 无权限角色：不能通过列设置看到无权模块、无权数据或被后端裁剪字段。

## 3. 用户流程

1. 用户进入任一后台业务模块的列表型/宽表型页面。
2. 只要页面存在业务表格，就应能在表格右上角使用统一“列设置”。
3. 用户点击“列设置”后，可以勾选显示/隐藏字段，并通过上移、下移调整字段顺序。
4. 用户在表头右侧拖动列边界，可以调整当前列宽。
5. 刷新页面、切换模块或重新进入页面后，列顺序、隐藏字段、列宽保持为当前用户本机设置。

## 4. 业务规则

- 状态流转：本卡不改变任何业务状态。
- 字段可见性：列设置只能调整当前角色已可见字段，不得新增或暴露后端未返回字段。
- 权限边界：菜单权限、接口权限、字段裁剪维持现状；列设置不是权限配置。
- 财务敏感字段：仓库、客服、业务员等角色不能通过列设置看到应付、利润、代理成本、付款信息等敏感字段。
- 操作列：默认保持可见；如允许隐藏，必须可通过恢复默认找回，不得让关键业务动作永久消失。
- 最少可见列：至少保留一列业务字段可见。
- 存储口径：第一阶段使用浏览器本地存储保存个人偏好，不新增数据库表，不做跨设备同步。
- 异常处理：本地配置损坏、旧字段不存在或列 key 变更时，自动回退默认列配置。
- 审计要求：列设置属于个人前端偏好，不写业务审计日志；原业务动作审计保持不变。

## 5. 不做范围

- 不发布 47。
- 不改数据库结构、Prisma 迁移或后端业务状态机。
- 不新增角色权限点。
- 不改变导出 Excel 字段顺序，除非现有导出本来直接复用页面列配置。
- 不处理表单字段、详情弹窗字段。
- 不强行改造嵌套详情小表、合计行复杂表、编辑型表格；这类表格如果风险高，必须列入未覆盖清单和后续任务卡。
- 不用前端列设置绕过后端权限裁剪。

## 7. 验收标准

- 验收 1：共享 `ManagedTable` 支持列隐藏、列排序、列宽拖拽、恢复默认和本地存储容错。
- 验收 2：“客服管理 -> 数据确认”完整支持列隐藏、列排序、列宽拖拽，刷新后配置保持。
- 验收 3：代码会话输出全局表格清单，标明每个后台业务表格“已接入 / 不适合本轮接入 / 后续任务卡”。
- 验收 4：业务、仓库、市场、客服、财务、基础资料、系统管理、报表中，普通业务表格尽量完成接入；未接入必须说明具体原因。
- 验收 5：列设置入口、弹窗文案、恢复默认、最少保留一列行为在已接入模块中保持一致。
- 验收 6：普通角色不能通过列设置看到权限外字段或财务敏感字段。
- 验收 7：本地存储损坏或旧列 key 失效时页面不报错，自动恢复默认列。
- 验收 8：关键操作列、审核按钮、确认按钮、详情按钮不能被静默移除到无法恢复。
- 验收 9：完成后给出下一轮只针对复杂表格的补齐建议，不影响本轮普通业务表格闭环验收。
