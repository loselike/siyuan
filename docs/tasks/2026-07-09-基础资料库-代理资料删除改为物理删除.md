# 2026-07-09-基础资料库-代理资料删除改为物理删除

## 1. 业务目标

基础资料库代理资料的 `删除` 必须执行物理删除，不再把删除当作停用；删除后该代理从列表、筛选、下拉选择和后续业务选择中彻底消失。

## 2. 使用角色

- 管理员、具备 `master-data:agents:write` 的角色：可删除代理资料。
- 只读角色：只能查看，不能删除。
- 客户、无基础资料权限角色：不能查看或删除代理资料。
- 删除操作必须记录审计日志，便于追溯谁删除了哪些代理。

## 3. 用户流程

1. 用户进入 `基础资料库 -> 代理资料`。
2. 勾选一条或多条代理资料。
3. 点击 `删除`。
4. 系统弹窗提示：`确认物理删除选中的 X 条代理资料？删除后不可恢复。`
5. 用户确认后：
   - 若全部代理都无业务引用，系统物理删除这些代理，刷新列表并清空已选项。
   - 若存在业务引用，系统阻止删除，并明确提示哪些代理不能删除、被哪些业务引用。
6. 删除成功后，被删除代理不再出现在代理资料列表、状态筛选结果、代理渠道绑定下拉、价格表导入代理简称下拉、客服默认查询网站代理匹配、待付款/付款申请代理银行账户选择。

## 4. 业务规则

- `删除` 是物理删除，不是停用。
- 删除失败时不能自动改成停用。
- 停用仍保留为独立状态能力，只影响后续选择，不回写历史数据。
- 已存在业务主表引用时，不允许物理删除代理，包括运单、订单、客服/仓库/物流相关运单引用、代理渠道、价格表、价格行、代理加价规则、付款申请、应付、已付款、收款银行账户同步记录等。
- 对无业务引用的代理，可连同仅属于该代理且未被财务业务引用的代理银行账户、代理默认查询网站配置一起物理删除。
- 批量删除整体校验：只要其中任一代理不可删除，本次批量删除不执行，并返回不可删除原因。
- 删除成功必须写 `master_data.agent.delete` 审计，包含删除前代理快照、删除数量、代理 ID、代理简称、操作人、操作时间、`hardDelete: true`。
- 删除不回写历史数据；已有历史业务如果需要代理名称展示，必须依赖历史单据自身快照或禁止删除保护。
- 权限和字段裁剪沿用基础资料库代理资料现有权限。

## 5. 不做范围

- 不发布 47。
- 不改客户资料删除逻辑。
- 不改代理渠道、公司渠道、渠道类别的删除规则。
- 不做历史业务数据回填。
- 不做数据库强制清空或绕过外键删除。
- 不把所有停用按钮改成删除；本卡只处理代理资料里的 `删除` 操作。

## 7. 验收标准

- 验收 1：代理资料点击 `删除` 后，确认弹窗明确显示 `物理删除`、`不可恢复`，不再出现 `停用` 文案。
- 验收 2：无业务引用的代理删除成功后，从代理资料列表和所有代理下拉选择中消失。
- 验收 3：有业务引用的代理不能删除，系统提示具体代理和引用原因，且该代理仍保留在列表中。
- 验收 4：批量删除成功后已选数量回到 `0`，列表刷新正常。
- 验收 5：删除成功写入 `master_data.agent.delete` 审计，且包含删除前快照和 `hardDelete: true`。
- 验收 6：删除失败不会把代理改成停用。
