# 个人中心-去掉登录日志并优化账号事件布局

## 1. 业务目标

优化个人中心排版，移除登录日志列表，只保留个人账号资料、修改密码和账号事件查看入口，让登录日志统一回到系统管理操作日志承接。

## 2. 使用角色

- 已登录员工：可打开个人中心，查看本人账号信息，修改本人资料和密码，查看本人账号事件。
- 管理员：同普通员工一样在个人中心只看本人账号事件；全量登录日志和审计仍去 `系统管理 -> 操作日志` 查看。
- 未登录用户：不能进入个人中心。
- 客户端用户：本卡不处理客户门户个人中心。

## 3. 用户流程

用户点击顶部 `个人中心`。

弹窗打开后，不再显示右侧 `登录日志` 表格；页面改为更清晰的账号资料布局：上方展示账号、角色、姓名、手机号、性别、昵称等个人资料，下方或右侧展示修改密码区域和 `账号事件` 区域。

用户修改资料后点击 `保存个人资料`，保存成功提示 `个人资料已更新`。

用户修改密码后点击 `保存新密码`，沿用现有密码强度校验，成功后提示重新登录。

用户点击 `查看账号事件` 或在账号事件区查看最近事件，只展示与本人账号相关的个人事件，例如资料修改、密码修改、首次登录改密、账号启停/重置密码相关提示；不展示登录 IP 列表。

## 4. 业务规则

- 登录日志不在个人中心展示；登录成功、登录失败、IP、地区、设备等统一在 `系统管理 -> 操作日志` 由管理员查看。
- 个人中心仅处理“本人账号事件”，不展示全量员工审计，不展示他人账号事件。
- 账号事件只读，不允许删除、编辑、导出。
- 账号事件可复用系统审计日志数据，但必须按当前登录用户裁剪。
- 个人资料保存继续只允许修改本人姓名、手机号、性别、昵称。
- 员工账号、角色、权限组只读展示，不能在个人中心修改。
- 修改密码继续要求当前密码、新密码、确认新密码，保持现有密码强度规则。
- 本卡不涉及费用口径、订单数据、客户数据、权限模型变更。
- 本卡不改变系统管理里的登录日志/审计日志能力。

## 5. 不做范围

- 不发布 47。
- 不改数据库结构。
- 不删除 `LoginLog` 历史数据。
- 不移除后端记录登录日志能力。
- 不做全量审计日志页面重构。
- 不新增管理员代改员工资料能力。
- 不改首次登录强制改密流程。
- 不处理客户门户个人中心。

## 7. 验收标准

- 验收 1：打开个人中心后不再出现 `登录日志` 标题和登录日志表格。
- 验收 2：打开个人中心时前端不再请求 `/api/auth/login-logs`。
- 验收 3：账号信息、修改密码区域排版清晰，1366px 宽度下输入框、按钮、标题不裁切、不拥挤。
- 验收 4：员工账号和当前角色只读展示，不能在个人中心修改。
- 验收 5：保存个人资料仍调用 `/api/auth/profile` 并提示 `个人资料已更新`。
- 验收 6：修改密码仍调用 `/api/auth/change-password`，成功后退出并要求重新登录。
- 验收 7：账号事件只展示当前登录用户本人相关事件，不展示其他用户审计。
- 验收 8：系统管理操作日志仍能查看登录成功/失败、IP、地区、设备等登录审计信息。
