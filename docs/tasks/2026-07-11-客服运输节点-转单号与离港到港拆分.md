# 转单号与离港到港运输节点拆分

## 1. 业务目标
把转单号、运输计划、实际离港和实际到港拆成清晰动作，避免在错误阶段写入混合事实。

## 2. 使用角色
客服维护转单号和运输节点；业务员按可见性查看；市场/仓库只读必要结果；财务不得推进物流状态；管理员全量。

## 3. 用户流程
双确认完成→“填写转单号”仅维护转单/分单和追踪网址→“维护运输计划”保存预计离港/到港但不变状态→实际离港点击确认并填 ATD/批注→实际到港填 ATA/批注→后续派送/签收。

## 4. 业务规则
- ETA=预计到港、ETD=预计离港、ATA=实际到港、ATD=实际离港，四字段不得混用。
- 保存计划不推进状态、不自动跳页面；确认动作才推进状态且幂等。
- 实际时间不得早于不合理边界，未来时间需按业务规则校验；统一北京时间/UTC 存储口径。
- 修改预计时间保留前后值；实际时间修改需更高权限和原因。
- 转单号动作不再提交 ETA/ETD。

## 5. 不做范围
不接真实轨迹；不推企业微信；不做船期预测；不发布 47。

## 6. 工程落地点
Shipment 四时间字段/迁移、Shared DTO/状态机、CustomerServicePage 拆弹窗、Operational API 白名单、审计、订单 E2E。

## 7. 验收标准
- 转单号、计划、离港、到港分别提交，任一动作不会写错其他字段。
- 保存 ETA/ETD 状态不变；确认 ATD/ATA 各推进一次并留批注。
- 财务/仓库直接调用推进接口被拒绝；业务员仅看到允许公开字段。
- 历史仅有 etaAt/etdAt 的记录兼容读取，不伪造成实际时间。
