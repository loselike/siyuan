# 2026-07-07-business-pending-review-list-fields.md

## 1. 业务目标

优化 `业务管理 -> 待审核运单` 列表字段，让业务员在审核前优先看到客户、目的地、渠道、货物数据和 RMB 应收总额，减少无关字段干扰。

## 2. 使用角色

- 业务员：查看自己名下客户的待审核运单，可执行详情、自审通过。
- 管理员：可在业务管理入口查看全部待审核运单并代业务自审。
- 财务：可在财务相关页面查看费用审核，不以本卡改动替代财务审核。
- 仓库/客户：不参与本卡，不开放待审核运单字段。

## 3. 用户流程

1. 用户进入 `业务管理 -> 待审核运单`。
2. 列表不再展示 `转单号` 和 `代理渠道`。
3. 原 `应收/代理计费重` 改为货物数据展示，包含重量、体积、件数、计费重。
4. 列表新增或保留 `应收` 字段，显示该票订单应收费用总额。
5. 应收金额统一按系统汇率折算为 RMB 展示。
6. 用户点击 `详情` 或运单号后，继续进入原待审核详情，不改变自审流程。

## 4. 业务规则

- 字段删除：待审核列表删除 `转单号`；删除 `代理渠道`。
- 货物数据：列表应展示货物重量、体积、件数、计费重；计费重优先使用订单计费重，缺失时按现有订单重量字段兜底。
- 应收口径：`应收` 为该订单所有有效应收费用的 RMB 合计。
- 汇率口径：非 RMB 应收费用按系统当前有效汇率折算为 RMB；缺少汇率时不得静默显示错误金额，应给出后端或前端可读异常/空值。
- 权限边界：本卡只展示应收总额，不展示应付、代理成本、利润、付款编号。
- 状态流转：不改变 `DRAFT / REVIEW_PENDING / WAITING_SORT` 流转。
- 审计要求：本卡为列表展示调整，不新增业务动作审计；若后端补列表汇总字段，应保持现有费用明细审计不变。

## 5. 不做范围

- 不改自审通过逻辑。
- 不改费用录入口径。
- 不改待审核详情页字段。
- 不改财务应收审核、业务成本审核、市场应付审核。
- 不发布 47。
- 不修复无关仓库页面类型错误。
- 不改数据库结构，除非现有接口无法稳定提供 RMB 应收合计。

## 6. 工程落地点

- Web：`apps/web/src/modules/finance/FinancePage.tsx` 的待审核运单列表列定义。
- API：`GET /api/shipments/review-pending` 如当前列表数据没有 RMB 应收合计，需要补受权限裁剪的汇总字段。
- Shared：如新增列表字段，需要补 `Shipment` 或专用 DTO 类型。
- 测试：补 Web 测试确认列表隐藏 `转单号/代理渠道`，展示货物数据和 RMB 应收；补 API 测试确认 USD 应收按系统汇率折算。

## 7. 验收标准

- 验收 1：`待审核运单` 列表不显示 `转单号` 列。
- 验收 2：`待审核运单` 列表不显示 `代理渠道` 列。
- 验收 3：列表展示货物重量、体积、件数、计费重。
- 验收 4：列表展示 `应收`，金额为有效应收费用 RMB 合计。
- 验收 5：存在 USD 应收时，按系统有效汇率折算为 RMB；RMB 应收直接计入。
- 验收 6：列表不展示应付、代理成本、利润、付款编号等敏感字段。
