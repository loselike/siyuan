# 任务卡标题

## 1. 业务目标

说明这张卡解决什么业务问题，用一句话概括结果；这里不写代码细节。

## 2. 使用角色

列出涉及角色，并明确谁能看、谁能操作、谁不能操作。

角色示例：业务员、客服、仓库、财务、管理员、客户。

## 3. 用户流程

用业务语言描述用户从哪里进入、做什么操作、看到什么结果。

流程必须包含入口、主要动作、成功结果和失败/异常反馈。

## 4. 业务规则

列出本卡涉及的状态流转、字段可见性、权限边界、费用口径、异常处理和审计要求。

没有涉及的规则写“本卡不涉及”，不要留空。

## 5. 不做范围

明确本张卡不处理什么，防止代码会话扩大范围。

例如：不做真实承运商接口、不做 47 发布、不做批量导入、不改历史数据。

## 6. 工程落地点

说明可能涉及的 API、页面、DTO、数据模型、权限、测试和状态文件。

只写必要边界，不要求规划会话写完整代码方案。
