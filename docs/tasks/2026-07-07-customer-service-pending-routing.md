# 客服管理新增待排货二级功能

## 1. 业务目标

在 `客服管理` 的 `转单号` 与 `待离港` 之间新增可用的 `待排货` 二级功能，让客服按仓库待排货模块同样格式查看待市场排货运单，并具备受控费用查看能力。

## 2. 使用角色

- 客服：可进入 `客服管理 -> 待排货`，只读查看待排货运单，可查看与客服职责相关的费用明细。
- 管理员：可查看同客服范围，并按已有权限看到更多受控费用字段。
- 客户：不进入客服后台；本卡不新增客户账号后台菜单。
- 业务员、仓库、财务：本卡不新增客服待排货操作权限。
- 市场：仍在 `市场管理 -> 待排货` 执行审核、修改、排货，本卡不抢市场操作。

## 3. 用户流程

客服进入 `客服管理`，左侧二级菜单顺序为：客服看板、数据确认、转单号、待排货、待离港、已离港、已到港、已派送、已签收、问题件、售后。

客服点击 `待排货` 后，页面展示与仓库 `待排货` 模块同样格式的宽表：日期、站点、业务员、客户编号、运单号、业务渠道、货物数据、业务成本、业务成本合计、选项、代理、代理渠道、应付成本、应付合计、操作。

客服侧该表为只读，操作列只允许 `查看费用` 和只读标识，不允许审核、修改、排货、出库。点击 `查看费用` 后弹出费用明细，先展示客服可看的应收费用和业务成本；应付、利润等敏感信息必须继续按后端权限裁剪，不因客服菜单开放而泄露。

如果没有待排货数据，显示空态：暂无待排货订单。

## 4. 业务规则

- 状态范围：`待排货` 只展示当前系统中已进入市场排货前队列的运单，按现有仓库待排货口径复用，不新增业务状态。
- 只读规则：客服不能在该页审核、修改、分配代理、选择渠道、确认出库或改变运单状态。
- 费用查看：
  - 客服可查看与客户沟通、数据确认相关的费用信息，至少包含应收费用、业务成本和合计。
  - 应付、代理敏感信息、利润字段必须继续由后端权限决定；前端不能仅靠隐藏字段做安全边界。
  - 仓库待排货已有格式和列工厂优先复用，避免新增重复表格口径。
- 权限边界：
  - 菜单可见不等于数据可见，后端费用详情接口仍必须按角色裁剪。
  - 客服不能看到其他系统未授权的财务敏感字段。
- 转单号/面单维护：本卡不修改 `转单号`、`上传面单` 逻辑。
- 问题件回复关闭：本卡不涉及。
- 状态流转：本卡不新增状态流转。
- 审计：只读查看不强制新增审计；若现有费用详情接口已有访问审计则沿用。

## 5. 不做范围

- 不做 47 发布。
- 不改数据库结构和 Prisma 迁移。
- 不改市场排货、仓库待出库、客服待离港状态流转。
- 不新增客服排货、审核、修改能力。
- 不新增客户门户功能。
- 不改费用口径，不开放利润或应付敏感字段。
- 不重构客服管理整体 UI。

## 7. 验收标准

- 验收 1：客服管理左侧二级菜单中，`待排货` 位于 `转单号` 和 `待离港` 中间。
- 验收 2：点击 `待排货` 后展示与仓库待排货同格式宽表，并能看到待排货运单。
- 验收 3：客服待排货操作列只有只读能力和 `查看费用`，没有审核、修改、排货、出库按钮。
- 验收 4：点击 `查看费用` 可看到该票应收费用、业务成本和合计。
- 验收 5：客服侧不得展示未授权的应付敏感字段、代理成本敏感信息或利润字段。
- 验收 6：本卡完成后，不影响 `转单号`、`待离港`、仓库待排货、市场待排货现有流程。
