# 水单到账与应收匹配统一闭环

## 1. 业务目标
统一业务登记水单、财务确认到账、匹配运单应收和撤销恢复余额的真实资金闭环。

## 2. 使用角色
业务员登记本人客户水单并查看状态；财务确认到账、匹配、调整、作废、归档；客服/仓库/市场不可见凭证和资金细节；管理员全量。

## 3. 用户流程
业务新增水单并上传凭证→财务待到账确认→进入可匹配余额池→在水单或运单应收选择同客户同币种项目→部分/全部匹配→撤销时恢复双方余额→归档。

## 4. 业务规则
- 水单编号/付款编号按确认口径唯一，重复提交返回明确错误。
- 只匹配同客户、同币种、已到账且有余额水单。
- 匹配金额不得超水单余额或应收未收金额；事务原子化。
- 运单审核与水单匹配解耦；审核后仍可匹配，但已匹配反审核须阻断或先撤销。
- 系统自动应收和人工应收统一到同一可匹配事实，不允许只在内存实现。

## 5. 不做范围
不对接银行流水；不自动 OCR；不重做应付；不迁移线上历史数据；不发布 47。

## 6. 工程落地点
WaterReceipt/Match/Voucher、ShipmentFinanceItem 与历史 ReceivableFee 兼容、Finance 页面/API/RBAC/审计/Prisma E2E。

## 7. 验收标准
- 重复编号、跨客户、跨币种、超额匹配均被后端拒绝且余额不变。
- 部分匹配、完全匹配、撤销匹配的水单和应收余额一致。
- 业务员只能看到本人客户，凭证访问受授权和对象归属校验。
- Prisma 路径覆盖系统自动应收，不以测试桩销账。
