# 全链路固定样本与跨角色闭环基线

## 1. 业务目标
用同一组固定数据证明一票正常件、一票成本异议件和一票问题件能被正确角色从录单走到签收，且任何阶段都不会消失或越权。

## 2. 使用角色
管理员配置和排障；业务员仅操作本人客户和订单；仓库仅理货/出库；市场仅排货；客服仅客服节点；财务仅财务事实。其他角色不得越权读写。

## 3. 用户流程
按 `docs/sunny-dev-index.md` 固定样本建立三票；逐角色登录完成录单、理货、审核、排货、出库、双确认、转单号、离港、到港、派送、签收和问题件；每步记录页面、接口、数据库和审计证据。失败时明确指出缺字段、错状态或无权限。

## 4. 业务规则
- 使用既有 9409/Daloday、AG-9409-UPS、SY-9409-001 等样本键。
- 每个动作必须核对当前状态、下一责任岗位、数据去向和 AuditLog/ShipmentEvent。
- 列表、详情、搜索、导出均验证后端数据范围和敏感字段裁剪。
- 不用管理员账号代替岗位验收；不以测试桩代替 Prisma。

## 5. 不做范围
不修复发现的问题；不创建生产数据；不发布 47；不改权限模型和数据库结构。

## 6. 工程落地点
扩展现有 Shared/API/Web E2E 固定样本和验收文档；优先复用 `app.*.e2e.test.ts`、workspace 测试和角色测试桩。

## 7. 验收标准
- 三票在任一阶段均能由运单台账检索，状态与数据库一致。
- 六类岗位的允许动作成功，禁止动作返回 403/业务拒绝且不产生脏审计。
- 业务员、仓库、客服响应中不出现不应查看的代理成本、应付、利润、银行字段。
- 输出逐节点证据表并标记真实通过/失败，不允许用“页面存在”销账。

## 8. 验证命令
```bash
npm test -w @siyuan/api -- --run src/modules/app.orders.e2e.test.ts src/modules/app.warehouse.e2e.test.ts src/modules/app.finance.e2e.test.ts
npm test -w @siyuan/web -- --run src/modules/workspace/workspace.test.tsx
npm run typecheck -w @siyuan/api && npm run typecheck -w @siyuan/web
```
