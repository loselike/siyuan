# 真实承运商轨迹适配首渠道

## 1. 业务目标
用一个真实高频渠道打通轨迹订阅、同步、状态归一化和客户可见，替换模拟承运商执行器。

## 2. 使用角色
客服查看和重试；业务员查看本人订单可见轨迹；客户仅看本人且 visibleToCustomer 的轨迹；管理员配置和排障；其他角色只读必要信息。

## 3. 用户流程
转单号保存→系统创建订阅任务→适配器调用供应商→Webhook 或轮询写入原始轨迹→归一化最新轨迹→客服看同步状态→业务/客户看允许公开轨迹；失败自动重试并可人工重发。

## 4. 业务规则
- 原始供应商事件不可覆盖；归一化事件另存，按供应商事件 ID 幂等。
- 内部 ShipmentEvent 与外部 TrackingEvent 严格分离。
- Webhook 验签、重放保护、限流、超时、退避重试和死信必须覆盖。
- 外部状态默认不自动推进关键内部状态，除非单独确认映射规则。
- 客户/业务可见性由后端裁剪，不仅前端隐藏。

## 5. 不做范围
只接一个供应商/渠道；不一次接全承运商；不自动签收财务；不发布 47。

## 6. 工程落地点
现有 CarrierTask/TrackingEvent、适配器接口、Webhook controller、调度/重试、TrackingPage、客户范围和 API E2E；删除或隔离生产路径中的 mock status。

## 7. 验收标准
- 一票真实转单号能获得至少两条真实事件并更新最新轨迹。
- 重复 Webhook 不重复写入，验签失败和越权查询被拒绝。
- 外部失败可重试，错误不覆盖最后成功轨迹。
- 客户只看到本人且允许公开的轨迹，内部备注不泄露。
