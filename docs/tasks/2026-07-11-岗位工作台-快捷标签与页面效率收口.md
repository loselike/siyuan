# 岗位工作台快捷标签与页面效率收口

## 1. 业务目标
在核心业务闭环稳定后，按岗位任务重排录单、排货、客服页面，并提供少量阶段快捷标签减少重复输入。

## 2. 使用角色
业务员使用录单模板；市场使用排货首屏；客服使用阶段标签；管理员可维护各阶段最多 10 个标签；其他岗位只看到职责页面。

## 3. 用户流程
用户进入岗位页面直接看到当前任务和关键字段；客服点击“+”选择或新增本阶段快捷批注，仍可自由编辑；列设置和横向滚动不遮挡主操作；空态、错误、无权限状态明确。

## 4. 业务规则
- 快捷标签按阶段隔离，最多 10 个，可排序/停用；不做复杂全局资料库。
- 标签只是批注输入辅助，不自动推进状态或改变费用。
- 页面调整不得删除现有操作、改变接口口径或弱化权限提示。
- 列表优先 ManagedTable，选择列固定第一列，操作列可见。
- 所有弹窗/抽屉/上传/错误态纳入同轮验收。

## 5. 不做范围
不改业务状态、数据库核心对象和权限模型；不做营销视觉；不发布 47；不在核心任务卡完成前先做表面美化。

## 6. 工程落地点
按 frontend-design 审查 Orders/Routing/CustomerService/Workspace，复用 ManagedTable 与现有 AntD 组件；快捷标签可用轻量配置模型/API，补 UI/权限/测试。

## 7. 验收标准
- 录单、排货、客服三个代表页面在 1366×900 首屏可看到核心字段和主操作。
- 每阶段快捷标签不超过 10 个，选择后可编辑且不自动换状态。
- 原有操作链路、权限裁剪、上传和日志全部保留。
- 820×900 与 1366×900 无遮挡、异常横向溢出或隐藏操作。

## 8. 验证命令
```bash
npm test -w @siyuan/web -- --run src/modules/orders src/modules/routing src/modules/customerService src/modules/shared/ui-table.test.tsx
npm run typecheck -w @siyuan/web
npm run build -w @siyuan/web
```

## 9. 风险与待确认
本卡依赖核心状态卡完成；若提前执行，只允许做不改变业务的布局调整。快捷标签是否允许普通客服新增，会议倾向允许但建议限定管理员维护、客服选择。
