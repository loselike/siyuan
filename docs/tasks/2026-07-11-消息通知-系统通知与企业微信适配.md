# 系统通知与企业微信适配

## 1. 业务目标
让成本异议、数据修改、转单号和问题件等跨岗位交接有可送达、可重试、可读的通知，不再依赖口头提醒。

## 2. 使用角色
系统按对象归属确定接收人；业务员接收本人订单通知；客服/市场/财务接收职责通知；管理员查看发送故障；用户只能读取自己的通知。

## 3. 用户流程
关键业务动作提交成功→同事务或可靠事件创建系统通知→接收人工作台看到未读→点击跳到对应对象→标记已读；异步适配器发送企业微信，失败可重试并显示结果。

## 4. 业务规则
- 通知记录接收人、事件键、对象类型/ID、摘要、状态、已读时间、幂等键。
- 业务动作成功不依赖企业微信成功；外部发送异步重试。
- 同一业务事件不得重复通知；重试不得重复业务动作。
- 消息正文按角色裁剪，不得包含代理成本、利润、银行账号等越权字段。
- 企业微信密钥仅服务端环境变量，不入日志/Git。

## 5. 不做范围
第一阶段只做系统通知，不做短信/邮件；企业微信方案未定前不写真实适配器；不发布 47。

## 6. 工程落地点
通知模型/迁移、事件服务、工作台通知入口、接收人解析、异步发送任务、企业微信适配器接口、权限与 E2E；复用现有审计/链路事件，不把 AuditLog 当通知表。

## 7. 验收标准
- 数据修改、转单号、问题件至少三类事件产生正确接收人的系统通知。
- 重复提交只生成一条通知，用户只能查询/已读自己的通知。
- 外部发送失败不回滚业务，保存失败原因并可重试。
- 敏感字段不进入通知响应和发送日志。

## 8. 验证命令
```bash
npm test -w @siyuan/api -- --run src/modules/app.orders.e2e.test.ts -t "notification|通知|idempotent"
npm test -w @siyuan/web -- --run src/modules/workspace/workspace.test.tsx -t "通知|未读|跳转"
npm run typecheck -w @siyuan/api && npm run typecheck -w @siyuan/web
```

## 9. 风险与待确认
系统通知阶段可执行；企业微信真实接入前需确认企业微信应用消息/群机器人方案、企业 ID、应用授权和接收人账号映射。
