# Sunny 长会话上下文轮换

## 目标

在同一 `/Users/j1ng/Tools/sunny` 工作目录中继续真实代码状态，同时把已经反复压缩、响应变慢或开始遗忘的聊天上下文替换为一个轻量新会话。轮换不能中断原子操作、丢失用户决定、覆盖并发修改，也不能把“创建新会话”扩大解释为发布或提交授权。

## 宽松触发门槛

| 状态 | 可观察条件 | 默认动作 |
| --- | --- | --- |
| Green | 观察到 0–1 次压缩；仍在同一功能或相关子功能；没有遗忘 | 正常继续 |
| Yellow | 观察到第 2 次压缩；或已完成约 3–4 个相关子功能；偶尔需要重复读取 | 刷新检查点，但继续当前会话 |
| Red | 观察到第 3 次压缩；连续两次非工具等待明显超过约 60 秒；出现遗漏、矛盾或重复劳动；Yellow 状态下准备跨明显不同模块 | 完成当前原子动作后轮换 |
| Immediate | 用户明确说“切换新会话”；压缩后无法可靠恢复事实；已经发生错误记忆 | 立即进入安全交接 |

不把测试、构建、Docker、网络或浏览器工具耗时计算为模型上下文变慢。不依赖不可见或不稳定的 token 数；压缩次数无法可靠判断时，以记忆准确性、重复劳动和用户体感为主。

## 连续命名

- 标准标题：`Sunny｜<业务主题>｜NN`。
- 同一目标继续：`Sunny｜仓库理货生命周期｜01` -> `Sunny｜仓库理货生命周期｜02`。
- 明显不同目标：重新命名并从 `01` 开始，例如 `Sunny｜水单匹配审核｜01`。
- 第一次轮换时旧标题不规范：先把旧会话重命名为 `01`，再创建 `02`。
- 归档状态由 Codex 任务归档能力管理，标题不追加“已归档”，保证搜索和编号稳定。

## 轮换事务

1. 等待当前文件写入、测试、构建、迁移、发布或外部动作返回明确结果。
2. 当前会话把 `docs/dev-now/_handoff-template.md` 的必要字段写入自己的状态文件，保持 2–4 KB。
3. 当前会话将自己的状态改为 `handed_off`；记录建议新标题和新状态文件名。
4. 创建相同工作目录的新会话，标题按编号递增；启动消息只引用交接文件，不粘贴旧聊天全文。
5. 新会话按 Mandatory Start Protocol 读取真实仓库状态，并完成五项接管确认。
6. 新会话创建自己的唯一 `docs/dev-now/<session-slug>.md`，状态为 `in_progress`，`续接自` 指向旧状态文件。
7. 新会话确认接管成功后，旧会话才执行归档。

如果第 4–6 步失败，旧会话恢复 `in_progress`，保留原编号并继续；不得留下两个同时写同一任务的 `in_progress` 状态文件。

## 创建新会话时的启动消息

```md
继续 Sunny 当前任务。工作目录：/Users/j1ng/Tools/sunny。

先完整读取：
1. AGENTS.md
2. .codex-state.md
3. git status --short
4. <旧状态文件路径>
5. 交接文件指定的相关代码

不要依赖旧聊天，不要扩大范围。先回复当前唯一目标、已完成与证据、未完成项、并发保护和第一项动作；一致后创建自己的状态文件并继续。
```

## 交接内容取舍

保留用户最终决定、验收标准、真实代码/数据事实、本任务文件、效果与安全证据、失败项、发布状态、下一动作、稳定附件。删除推理过程、重复讨论、完整日志、完整 diff、无关历史功能和可以通过路径重新读取的大段代码。

截图或附件仍位于 `/var/folders/.../T/` 等临时目录时，轮换前复制到当前任务明确认领的稳定证据目录；没有稳定路径就把关键观察写成文本并标记原图可能失效。

## 归档与恢复

- 归档只发生在新会话完成五项接管确认之后。
- 新会话不准确、工具不可用、状态文件冲突或创建失败时，不归档旧会话。
- 用户可随时要求恢复旧会话；恢复前先确认新会话没有正在写同一文件，避免双写。
- `.codex-state.md` 只记录完成和高信号结论，不用于传递进行中的长对话。

## 第一次真实效果验收

首次收到“切换新会话”时必须验证：新会话不读取旧聊天也能准确说出当前目标、文件、效果证据、未验证项和下一动作；新状态文件正确续接；旧会话只在确认后归档。五项任一不一致，轮换机制视为未通过并回到旧会话修正。
